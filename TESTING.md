# Правила тестирования

- Каждое изменение игровой механики сопровождается автотестом.
- Каждая пользовательская механика сопровождается новым или обновлённым этапом внутриигрового обучения.
- Каждая фича добавляется в `QA_CHECKLIST.md` с точными действиями и ожидаемым результатом.
- Перед каждым коммитом и push выполняется `./run_tests.sh`.
- Целевое покрытие всего тестируемого кода — 60–80%; нижняя граница 60% обязательна.
- В первую очередь покрываются игровая логика, состояния, время, экономика, ввод, сохранения и переходы стадий.
- Визуальная отрисовка дополнительно проверяется вручную в Godot, поскольку line coverage не подтверждает корректность изображения.
- Git hook `pre-commit` не позволяет создать коммит при падающих тестах; `post-commit` отправляет успешный коммит в GitHub.

Текущий раннер проверяет ввод, игровые сутки и полный жизненный цикл моркови. При росте проекта игровая логика будет вынесена из отрисовки в отдельные модели, чтобы реальное покрытие можно было измерять автоматически.
