### Запуск Git-проверок из hook в worktree

При проверке FAIR-00 обнаружено: `tools/planning/test_task_batch.py` наследует локальные переменные Git вызывающего hook (`GIT_DIR`, `GIT_INDEX_FILE` и другие). ## Проверки отдельной wiki

Общий контракт иконок проверяется `ItemIconContractSuite` в полном наборе и профильно через `tools/item_icon_contract_review.gd`. Для художественной ревизии выполнить `python3 tools/check_art_review.py` и `python3 tools/test_art_review.py`: весь реестр должен быть покрыт партиями без повторов, каждый исходный PNG имеет правильный хеш/размер, цвет и рамка валидны. Этот контроль не заменяет выбор дизайна или художественный просмотр. После новых предметов/ресурсов снимок и партии пересоздаются инструментами, указанными в плане.

Для изменений в `wiki/` дополнительно выполните `pnpm check` в этой папке: актуальный экспорт Godot → проверка ссылок и спрайтов → TypeScript → production-сборка → Node-тесты. Игровые проверки перед commit/push также обязательны. CI содержит независимый job wiki с Godot и Node 24.

Проверяются весь предметный и рецептурный реестр, миссии, жители и станки, физическое существование каждого PNG, размеры источников, реальные направления и действия, русский поиск, ингредиенты и партии, localhost HTTP, чужой занятый порт, доступ только к сборке, восстановление предыдущего сайта при ошибке и bundle macOS. В браузере дополнительно проверить поиск, ссылки, паузу/ракурсы/кадры, расчёт партий, уровни станка и читаемость страницы. Сам экспорт не использует слоты пользователя.

- Каждое изменение игровой механики сопровождается автотестом.
- Каждая пользовательская механика сопровождается новым или обновлённым этапом внутриигрового обучения.
- Каждая фича добавляется в `QA_CHECKLIST.md` с точными действиями и ожидаемым результатом.
- Перед каждым коммитом и push выполняются `tools/check_architecture.sh` и `./run_tests.sh`.
- `run_tests.sh` автоматически ищет исполняемый Godot в порядке:
  `FARM_GODOT_BIN` → `tools/Godot.app/Contents/MacOS/Godot` → стандартный `godot` из PATH.
- Если нужно принудительно использовать другой билд, экспортируй путь `FARM_GODOT_BIN`.
- Архитектурный gate также запускает `tools/quality/check_documentation.py`: обязательные документы должны существовать, а каждая локальная Markdown-ссылка — вести в реальный файл или каталог.
- Тесты разделены на профильные наборы для игровых механик, интерфейсов, спрайтов, конструктора и регрессий производительности; `tests/test_game.gd` только запускает агрегаторы и собирает результат. Новые небольшие suites подключаются через агрегаторы, не раздувая общий runner.
- Политика покрытия остаётся 60–80% для тестируемой логики. Godot 4.7 не предоставляет встроенное построчное покрытие, поэтому проект не публикует выдуманный процент: контроль качества сейчас измеряет более 3400 поведенческих утверждений, целостность контента и архитектурные ограничения.
- В первую очередь покрываются игровая логика, состояния, время, экономика, ввод, сохранения и переходы стадий.
- Визуальная отрисовка дополнительно проверяется вручную в Godot, поскольку line coverage не подтверждает корректность изображения.
- Любая строка `ERROR:` движка в журнале тестов блокирует публикацию, даже при успешном счётчике утверждений. Отсоединённые тестовые сцены используют проектный размер кадра без обращения к отсутствующему viewport; этот сценарий покрывает `tree_occlusion_suite.gd`.
- Тесты поэтапной навигационной сетки ожидают завершение всего числа поставленных клеток. Фиксированное число кадров не является гарантией завершения: бюджет на кадр ограничен временем и зависит от нагрузки машины. Производительность измеряется отдельными стендами.
	Сценарий `test_runtime_debug_overlay_classifies_navigation_grid` тоже ограничивает ожидание фактическим размером очереди, а не500пакетами: при бюджете1мс один пакет может обработать только одну клетку. Рабочий лимит F10 остаётся прежним.
- Git hook `pre-commit` не позволяет создать коммит при падающих тестах; `post-commit` показывает исторический счётчик без отправки. Готовая реализация публикуется в ветке и PR, затем проходит Tech Lead Agent и Team Lead Agent по `docs/CODE_REVIEW.md`. Слияние в `main` разрешено после принятия текущего SHA и решения тимлида; прежний прямой пакетный push не обходит ревью.

CI загружает зафиксированную версию Godot 4.7.1 и запускает тот же quality gate на каждом push и pull request. В `jobs.test.env` задан общий абсолютный `FARM_GODOT_BIN`: его наследуют architecture, игровые тесты, smoke и performance; путь не должен быть ограничен только последними шагами. Перед architecture выполняется штатный импорт ресурсов в чистом checkout. Новая функция должна попасть в подходящий suite; новый suite не может превышать 350 строк.

## Комментарии к коду и тестам

- Перед каждым обычным или статическим методом располагается комментарий `##` на русском языке, описывающий ответственность метода без пересказа реализации построчно.
- Перед каждым тестовым методом располагаются три русские строки: `Сценарий`, `Исходное состояние` и `Ожидаемый результат`. По ним должно быть понятно назначение теста без чтения его тела.
- Английские идентификаторы допустимы внутри исполняемого кода и строк проверок, но не используются как основной язык комментария.
- Проверка `test_all_methods_have_russian_documentation` рекурсивно сканирует каталоги `scripts` и `tests`; новый недокументированный метод блокирует коммит.
- Архитектурные лимиты считают только исполняемые строки: полезная документация не заставляет искусственно объединять методы или сокращать пояснения.
