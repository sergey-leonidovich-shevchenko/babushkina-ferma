# Рабочие договорённости

- По завершении согласованных изменений делай отдельные коммиты по смыслу и сразу отправляй их в настроенный Git remote. Пользователь постоянно разрешает обычные commit и push в этом проекте; повторное подтверждение не требуется.
- Перед публикацией выполняй проверки из `TESTING.md`. Коммиты должны содержать соответствующие тесты и документацию. Не объединяй несвязанные изменения в один коммит.
- Не используй force push и не переписывай опубликованную историю без отдельного указания пользователя. Если проверки или push не прошли, исправь доступную причину и явно сообщи, что осталось неопубликованным.
- Новую работу выбирай по ID из [бэклога](docs/backlog/2026-10/README.md). Для отдельной задачи создавай ветку `codex/<id-строчными>-<короткое-имя>`, например `codex/opt-02-storage-frame-budget`. GitHub issues для этого плана не требуются. Статусы, зависимости и подтверждения выполнения веди в файлах бэклога; порядок описан в `docs/BACKLOG_WORKFLOW.md`.
- Мебель, верстаки, станки, лавочки, колодцы, телеги и подобные предметы имеют только три основных ракурса: влево, вправо и вниз к игроку. Не рисуй и не подключай диагональный разворот или глухую заднюю сторону. Сохраняй прямую привязку к сетке и пропорции; подробности в `docs/SPRITE_STANDARD.md`. Правило повторно подтверждено пользователем 14 октября 2026 года.
- Дизайн-макеты сохраняй отдельно от игровых ресурсов. Сначала показывай варианты; перенос в игру выполняй после выбора пользователя.

Договорённость о постоянных commit и push подтверждена пользователем 11 октября 2026 года.
