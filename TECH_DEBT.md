# Реестр технического долга

Полный аудит выполнен 2 августа 2026 после глобального рефакторинга. Долг разделён на закрытый, контролируемый автоматикой и отложенный по объективной причине. Это живой реестр: новый пункт обязан иметь риск, критерий завершения и приоритет.

## Результат прохода

| Область | До | После |
|---|---:|---:|
| `scripts/game.gd` | 2057 строк, 123 функции состояния/логики/отрисовки | 1007 строк, только оркестрация и совместимый фасад |
| Отрисовка | внутри `game.gd` | `game_renderer.gd`, 643 строки, отдельный CanvasItem-слой |
| Состояние | десятки несвязанных полей | агрегат `GameState` с `PlayerState`, `InventoryState`, `WorldState` |
| Количества предметов | длинные `match` в чтении, изменении, импорте и экспорте | единый каталог `InventoryState.counts` и универсальные операции |
| Контент | словари без проверки ссылок | владельцы по системам + `ContentRegistry.validate()` при старте и в тестах |
| Сохранение | v1, запись сразу поверх файла | v2, миграция v1, временный файл, проверка JSON, `.bak` и восстановление |

| Тесты | один файл на 922 строки | раннер на 41 строку и 5 тематических suites до 279 строк |
| Автоматизация | только локальный hook | локальный quality gate и GitHub Actions на Godot 4.7.1 |
| Регрессия | 547 проверок | 581 проверка, 0 ошибок |
| Производительность | стабильные 60 FPS | стабильные 60 FPS / 16.66 мс |

## Закрыто

- **SRP:** данные, renderer, ввод, сохранение, контент и тестовые сценарии имеют отдельных владельцев.
- **OCP:** зарегистрированный предмет изменяется, сохраняется и попадает в динамический рюкзак без новой ветки в `game.gd`.
- **LSP/ISP:** renderer зависит от малого типизированного контракта `game_context.gd`; чистые layout-расчёты вынесены в `PresentationSystem`.
- **DIP:** добыча ресурсов использует публичную операцию инвентаря, а не меняет поля конкретных ресурсов.
- Дефолтные враги, животные, залежи, растения, товары и этапы обучения перенесены к системам-владельцам.
- Межкаталожные ссылки рецептов, лута, миссий, магазинов, спавнов, локаций и переводов валидируются до начала игры.
- Сохранение не оставляет частично записанный основной файл и умеет восстановить последнюю полную копию.
- Архитектурный gate запрещает возвращать `draw_*` в `game.gd`, превышать лимиты размеров и коммитить whitespace-ошибки.

## Контролируемый остаток

### P1 — при расширении соответствующей подсистемы

- Остаточные состояния боя, окон и заданий пока находятся в `GameContext`. Переносить их в отдельные typed states следует вместе с изменением сохраняемой модели конкретной механики; массовая миграция без продуктовой пользы увеличит риск сохранений. Критерий: новое сохраняемое изменяемое поле не добавляется напрямую в `game_context.gd`; временный номер страницы модального окна допустим.
- `game_renderer.gd` остаётся единым CanvasItem с 611 исполняемыми строками ради одного draw pass. При превышении автоматического лимита 700 он разделяется на world renderer и UI renderer. Критерий уже исполняется `tools/check_architecture.sh`.
- Каталоги представлены типизированно проверяемыми словарями, а не `.tres`-ресурсами. Переход на custom `Resource` нужен при появлении редактора контента или внешнего дизайнера; сейчас runtime-валидатор даёт более простой и надёжный pipeline.

### P2 — инструменты и визуальное качество

- Настоящий line/branch coverage для GDScript 4.7 пока не входит в Godot. Существующий набор измеряет 1607 поведенческих утверждений, но не выдаётся за процент строк. Экспериментальный `gd-tools` будет оценён после стабильного релиза и поддержки текущего собственного раннера; до этого обязательны tests + content validation + architecture gate.
- Автоматические golden screenshots для HUD, рюкзака, магазина и крафта остаются кандидатом: снимки должны выполняться на фиксированном software renderer, иначе различия драйверов создадут ложные падения.
- Семнадцать движущихся типов пока не имеют восьми полноценных направлений по 3–5 кадров. Владелец — `AnimationAssetRegistry`, критерий закрытия и очередность — [стандарт спрайтов](docs/SPRITE_STANDARD.md) и [аудит](SPRITE_AUDIT.md); новый тип без записи блокирует тест.
- В пользовательских сообщениях ещё есть строки-фолбэки на русском. Новая пользовательская строка обязана добавляться через `LocaleSystem`; существующие заменяются при затрагивании соответствующего экрана.
- Пул объектов не нужен по текущему профилю: после полного прохода 60 FPS, аллокации спавна не являются узким местом. Пункт активируется только по данным profiler.

## Правило нового долга

Любой новый TODO добавляется сюда с владельцем, риском и проверяемым критерием завершения. `tools/check_architecture.sh` и `./run_tests.sh` должны проходить перед каждым commit/push.
