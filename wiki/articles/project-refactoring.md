# Рефакторинг: инструменты по назначению

**Поручение пользователя 25 октября 2026.** После полного завершения текущей VFOLIAGE-010 разработчик приоритетно начинает [REFACTOR-01 — ведомость и карта переносов](#/development/tasks/refactoring--REFACTOR-01), затем упорядочивает tools. Текущие исправления PR №7, ревью и учёт не прерываются. Сам перенос ещё не выполнен.

[Эпик и карточки](#/development/epics/refactoring--REFACTOR) · [Подробный контракт](../../docs/epics/refactoring-2026-10/README.md) · [Исходная ведомость](../../docs/reports/refactor-00/inventory.json).

В корне принятой main у tools 750 файлов; открытый PR №7 увеличивает их до 762. Там смешаны QA, работа с ассетами, сборка, общие проверки и ручные стенды. Первый полезный выпуск группирует их по ответственности и оставляет в корне не более 30 исходников публичных команд с объяснёнными исключениями. Python и Godot одной подсистемы остаются рядом.

Порядок: аудит ссылок и входов → общие пути/репозиторные команды → QA/asset/build/dev-пакеты → README и guard. Каждый этап имеет отдельную ветку/PR и собственную приёмку. Тесты не теряются в новых папках; новые внутренние инструменты больше не попадают автоматически в корень.

Аудит также проверит scripts/systems, scripts/presentation и tests/suites. Их дальнейшие переносы выделены в отдельные карточки 04/05; исторические reports и адресные каталоги ассетов не переименовываются по одному счётчику. До переноса фиксируются UID, потребители и точные проверки.

Главный риск — сломать импорт, preload, CI, Wiki или прежнее доказательство. Сохранённые планы, капсулы, source SHA, raw и неудачные попытки остаются неизменными; исторические readers читают свой Git base/капсулу. Старые сотни имён не превращаются в сотни пустых wrappers. Механический перенос отделяется от изменения поведения.

Это техническая очередь по новому прямому поручению. Она не разрешает новые механики/карты и не закрывает общий FPS или VMAP-003. После первого выпуска tools возвращается обычный маршрут первой локации; оставшиеся адресные переносы согласуются Team Lead по ведомости.
