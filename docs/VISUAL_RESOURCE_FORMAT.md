# Паспорт графического ресурса — VPIPELINE-002/003/005

Версия схемы — `1`. [Рабочий каталог](../assets/game/visual_resources.json), [загрузчик](../scripts/systems/visual_resource_catalog.gd), [валидатор](../tools/assets/contracts/visual_resources.py). В этой задаче переведён один пилот: действующий дубовый стол, три вида. Это контракт подготовки графики, не внедрение нового художественного набора.

## Две таблицы и один владелец геометрии

`textures` связывает технический ID текстуры с файлом, SHA256, пиксельными размерами, типом листа и проверяемыми параметрами `.import`. `resources` хранит семантический ID объекта и ссылается на ID текстур. Переименование PNG меняет `textures.<id>.file` и импортную связь; размеры, опоры, ракурсы и идентификатор предмета остаются прежними.

Инвентарный `world_sprite_manifest.json` и производные UI-индексы также требуют обновления или пересборки при настоящей миграции путей. Это не меняет ID и геометрию паспорта. JSON загружается штатным JSON-ресурсом через `preload`; сборки с выборочным экспортом сцен должны отдельно учитывать динамические пути PNG. Готовый PCK этой задачей не проверяется, упаковка остаётся VRELEASE.

| Поле ресурса | Значение |
|---|---|
| `kind`, `space` | Назначение (`prop`, `icon`, `tile`, `actor_frame`) и единицы `world`/`ui` |
| `owner`, `task`, `source` | Владелец, задача, происхождение. Для старого runtime — commit; для нового мастера — файл вне импорта и SHA256 |
| `filter`, `sampling_family` | Согласованные режим и семейство из [политики фильтрации](../assets/game/visual_sampling.json), отдельно от PNG-импортера |
| `default_quality` | Имя существующего варианта, присутствующего во всех ракурсах |
| `views` | Реальные направления. Для пропсов строго `south`, `west`, `east` |
| `logical_size` | Прямоугольник вписывания в мировых или экранных единицах, не пиксельный размер файла |
| `footprint_size` | Отдельное физическое основание, используемое коллизией |
| `pivot` | Нормализованная точка опоры относительно вписанного рисунка; `[0.5,1]` — низ по центру |
| `variants` | Качество → `texture` и целочисленный `source_rect=[x,y,w,h]` в пикселях соответствующей текстуры |

Ракурсы одного предмета могут иметь разное соотношение сторон. Варианты качества одного ракурса обязаны сохранять соотношение сторон; они не переопределяют мировые размеры или опору. `source_rect` не включает поворот или отражение. У мебели нет диагональных и задних ресурсов; старый индекс направления `2` переводится в передний существующим `FurnitureFacingSystem`.

`layout=standalone` требует сохранить всю видимую альфу внутри области. Для `atlas` проверяется область и непустая альфа выбранного кадра, без требования включить соседние рисунки. Padding подключён VPIPELINE-004; назначения цвета/данных — VPIPELINE-005. Анимационные последовательности остаются VPIPELINE-007/008 и VANIM.

## Назначение цвета и чисел

Каждая текстура этого визуального паспорта явно объявляет `intent=color_srgb`. `VisualResourceCatalog` отклоняет неизвестное/числовое назначение рисунка; дескриптор возвращает `texture_intent`, а `shader_binding` отдаёт сырой общий Texture2D с его ролью. Это не меняет `sampling_family`, размеры или опору. `CanvasTexture` предназначен для CanvasItem и не передаётся напрямую в shader sampler.

[Политика назначений](../assets/game/visual_texture_intents.json) также содержит `data_rgba8`: lossless без цветового преобразования, исправления прозрачного края, premultiply, normal/channel преобразований, уменьшения и mipmaps. Игровых масок пока нет; будущий владелец воды/растительности создаёт их по этому контракту. `TextureIntentSystem.material` проверяет простые `canvas_item` sampler2D: у цвета обязателен `source_color`, у данных запрещён; явные nearest/linear и `repeat_disable`, без неизвестных объявлений и привязок. Материал удерживается владельцем вне покадрового цикла.

`python3 tools/run.py assets.contracts.texture_intents` сверяет политику, импорт и числовую нативную матрицу Compatibility/Mobile LDR/HDR; [отчёт VPIPELINE-005](reports/visual-overhaul/vpipeline-005/README.md) объясняет все допуски, отрицательные контроли и границы. Сам импорт не гарантирует правильную роль sampler.

## Реальный пилот

VPIPELINE-004 дополнительно подключает [пакет UI-атласов](reports/visual-overhaul/vpipeline-004/README.md) отдельным производным паспортом: четыре страницы, 386 предметных ID, поля RGBA, отдельные уровни и явный `painted_atlas`. Он владеет областями миниатюр, а основной паспорт пропса продолжает владеть геометрией стола. Обычные линейные атласы без проверки по-прежнему запрещены.

`prop.rustic_table` использует текущие три PNG без перерисовки. Вниз: исходная область `240×160`, рамка `96×72`, показ `96×64`, основание `72×48`. Влево/вправо: рамка `72×72`, основание `48×72`, показ соответственно `53.7×72` и `53.1×72`. Опора всех видов остаётся у пола; узкий боковой рисунок не растягивается до квадрата.

`FarmLifeVisualSystem.profile()` читает эти размеры из паспорта; `HouseFurnitureVisualSystem` получает текстуру и нарезку по ID. Аудит контента использует разрешённые профили. F12 получает ID, ракурс, область, фактический размер вписанного рисунка и основание из того же источника. У палитры стола теперь та же геометрия, что у игры. При snap левая кромка основания выравнивается с учётом его ширины на выбранной сетке 6/12/24. Текущий адаптер палитры подключает пропсы с нижней центральной опорой; другие типы и произвольные опоры развиваются в VEDITOR.

Записи сохранений и опубликованных уровней сохраняют прежний формат. Уровни, хранящие `asset_path`, не получают автоматическую миграцию при переименовании: это отдельная работа VPIPELINE-009/VEDITOR/VCOMPAT. Все 386 иконок также сохраняют действующий `PreparedItemIconSystem`; их массовый перенос относится к VPIPELINE-006/VICON.

## Фильтрация, качества и стоимость

У пилота есть только реальный `standard`. В VPIPELINE-003 принят `painted_world` / `linear` для трёх отдельных рисунков стола. [CanvasTexture](https://docs.godotengine.org/en/stable/classes/class_canvastexture.html) применяется только на пути рисования; исходный Texture2D, область, опора и размеры сохранены. Старое полотно мира/UI явно закреплено на nearest, часы используют painted_ui/linear. F12 и опубликованные уровни используют тот же паспорт и удерживаемые обёртки. Обычные линейные атласы без проверки запрещены; отдельный допуск подготовленных страниц реализован в VPIPELINE-004. [Нативное сравнение и ограничения](reports/visual-overhaul/vpipeline-003/README.md).

Паспорт читается один раз, разрешённые дескрипторы кешируются и доступны только для чтения. Проверка SHA256/альфы выполняется до публикации, а не каждый кадр. Игра сохраняет те же три текстуры; GPU-readback для поиска границ стола больше не нужен. Прирост FPS не заявляется.

## Проверка

`python3 tools/run.py assets.contracts.visual_resources` проверяет настоящий каталог. `python3 tools/run.py assets.contracts.test_visual_resources` создаёт собственные PNG: переименование, двойная плотность, порча изображения, обрезанная/пустая альфа, выход за границы, потерянное качество, дубли ID, неправильный импорт и раздельный мастер. Тестовое качество не является новым художественным ресурсом игры.

Профиль Godot: `tools/assets/contracts/visual_resources_review.gd`; общий набор включает `VisualResourceSuite`. `tools/assets/contracts/visual_resource_capture.gd` снимает комнату и лист трёх ракурсов в отдельном профиле, при одной камере и остановленной симуляции. [Отчёт](reports/visual-overhaul/vpipeline-002/README.md). Перед commit/push обязателен `TESTING.md`, для Wiki — `pnpm check`.
