# Паспорт графического ресурса — VPIPELINE-002

Версия схемы — `1`. [Рабочий каталог](../assets/game/visual_resources.json), [загрузчик](../scripts/systems/visual_resource_catalog.gd), [валидатор](../tools/visual_resources.py). В этой задаче переведён один пилот: действующий дубовый стол, три вида. Это контракт подготовки графики, не внедрение нового художественного набора.

## Две таблицы и один владелец геометрии

`textures` связывает технический ID текстуры с файлом, SHA256, пиксельными размерами, типом листа и проверяемыми параметрами `.import`. `resources` хранит семантический ID объекта и ссылается на ID текстур. Переименование PNG меняет `textures.<id>.file` и импортную связь; размеры, опоры, ракурсы и идентификатор предмета остаются прежними.

Инвентарный `world_sprite_manifest.json` и производные UI-индексы также требуют обновления или пересборки при настоящей миграции путей. Это не меняет ID и геометрию паспорта. JSON загружается штатным JSON-ресурсом через `preload`; сборки с выборочным экспортом сцен должны отдельно учитывать динамические пути PNG. Готовый PCK этой задачей не проверяется, упаковка остаётся VRELEASE.

| Поле ресурса | Значение |
|---|---|
| `kind`, `space` | Назначение (`prop`, `icon`, `tile`, `actor_frame`) и единицы `world`/`ui` |
| `owner`, `task`, `source` | Владелец, задача, происхождение. Для старого runtime — commit; для нового мастера — файл вне импорта и SHA256 |
| `filter` | Явное требование `nearest`/`linear`, отдельно от настроек PNG-импортера |
| `default_quality` | Имя существующего варианта, присутствующего во всех ракурсах |
| `views` | Реальные направления. Для пропсов строго `south`, `west`, `east` |
| `logical_size` | Прямоугольник вписывания в мировых или экранных единицах, не пиксельный размер файла |
| `footprint_size` | Отдельное физическое основание, используемое коллизией |
| `pivot` | Нормализованная точка опоры относительно вписанного рисунка; `[0.5,1]` — низ по центру |
| `variants` | Качество → `texture` и целочисленный `source_rect=[x,y,w,h]` в пикселях соответствующей текстуры |

Ракурсы одного предмета могут иметь разное соотношение сторон. Варианты качества одного ракурса обязаны сохранять соотношение сторон; они не переопределяют мировые размеры или опору. `source_rect` не включает поворот или отражение. У мебели нет диагональных и задних ресурсов; старый индекс направления `2` переводится в передний существующим `FurnitureFacingSystem`.

`layout=standalone` требует сохранить всю видимую альфу внутри области. Для `atlas` проверяется область и непустая альфа выбранного кадра, без требования включить соседние рисунки. Проверки padding, цветовых/data-текстур и полной анимационной последовательности развиваются отдельными VPIPELINE-004/005/007/008 и VANIM.

## Реальный пилот

`prop.rustic_table` использует текущие три PNG без перерисовки. Вниз: исходная область `240×160`, рамка `96×72`, показ `96×64`, основание `72×48`. Влево/вправо: рамка `72×72`, основание `48×72`, показ соответственно `53.7×72` и `53.1×72`. Опора всех видов остаётся у пола; узкий боковой рисунок не растягивается до квадрата.

`FarmLifeVisualSystem.profile()` читает эти размеры из паспорта; `HouseFurnitureVisualSystem` получает текстуру и нарезку по ID. Аудит контента использует разрешённые профили. F12 получает ID, ракурс, область, фактический размер вписанного рисунка и основание из того же источника. У палитры стола теперь та же геометрия, что у игры. При snap левая кромка основания выравнивается с учётом его ширины на выбранной сетке 6/12/24. Текущий адаптер палитры подключает пропсы с нижней центральной опорой; другие типы и произвольные опоры развиваются в VEDITOR.

Записи сохранений и опубликованных уровней сохраняют прежний формат. Уровни, хранящие `asset_path`, не получают автоматическую миграцию при переименовании: это отдельная работа VPIPELINE-009/VEDITOR/VCOMPAT. Все 386 иконок также сохраняют действующий `PreparedItemIconSystem`; их массовый перенос относится к VPIPELINE-006/VICON.

## Фильтрация, качества и стоимость

У пилота есть только реальный `standard`, с прежним `nearest`. Поле `filter` хранит требование; смешанная фильтрация семейств реализуется в VPIPELINE-003. В Godot фильтр — свойство [CanvasItem](https://docs.godotengine.org/en/stable/classes/class_canvasitem.html#class-canvasitem-property-texture-filter), поэтому запись `linear` в паспорте сама по себе не переключает общий игровой CanvasItem. Новые режимы не включаются этой задачей.

Паспорт читается один раз, разрешённые дескрипторы кешируются и доступны только для чтения. Проверка SHA256/альфы выполняется до публикации, а не каждый кадр. Игра сохраняет те же три текстуры; GPU-readback для поиска границ стола больше не нужен. Прирост FPS не заявляется.

## Проверка

`python3 tools/visual_resources.py` проверяет настоящий каталог. `python3 tools/test_visual_resources.py` создаёт собственные PNG: переименование, двойная плотность, порча изображения, обрезанная/пустая альфа, выход за границы, потерянное качество, дубли ID, неправильный импорт и раздельный мастер. Тестовое качество не является новым художественным ресурсом игры.

Профиль Godot: `tools/visual_resources_review.gd`; общий набор включает `VisualResourceSuite`. `tools/visual_resource_capture.gd` снимает комнату и лист трёх ракурсов в отдельном профиле, при одной камере и остановленной симуляции.
