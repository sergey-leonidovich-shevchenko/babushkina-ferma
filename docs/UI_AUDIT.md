# Аудит интерфейса

Этот документ превращает визуальные замечания в проверяемые требования. Он используется перед изменением любого окна вместе с [общим стандартом UI](UI_GUIDE.md), а текущий машинный результат хранится в [JSON-отчёте](reports/ui_layout_audit.json).

## Обязательные требования

| ID | Требование | Автоматическая проверка |
|---|---|---|
| UI-R01 | Любая кнопка целиком находится внутри своего корпуса и не пересекает соседнюю | containment и pairwise overlap |
| UI-R02 | Минимальная область нажатия — 28×28 логических пикселей; целевой размер для основных действий — 32 px по высоте | touch target |
| UI-R03 | Текст не касается художественной рамки: минимум 4 px сверху и снизу после учёта ascent/descent реального шрифта | font metrics |
| UI-R04 | Резные кнопки конструктора имеют боковой safe-padding 10–18 px, длинная строка уменьшается и только затем сокращается | fitted label |
| UI-R05 | Название, служебный путь и миниатюра ресурса занимают независимые области | catalog baselines |
| UI-R06 | Спрайт сохраняет пропорции и центрируется внутри content-rect; подпись не может отнимать случайную часть кадра | atlas grid and badge |
| UI-R07 | Динамические имена, статусы, ошибки и числа обязаны измеряться текущим шрифтом | dynamic fitted label |
| UI-R08 | Основные контрольные экраны снимаются в 1152×648 и входят в regression manifest либо в профильный эталон конструктора | golden reference |
| UI-R09 | Выбранное состояние задаётся встроенным художественным спрайтом, а не внешней жёлтой рамкой | component contract |
| UI-R10 | Изменение геометрии сопровождается сценарным тестом на исходное и ожидаемое состояние | test gate |

## Аналитика 3 сентября 2026

- Просканировано 35 renderer-модулей: 259 однострочных вызовов используют общее адаптивное вписывание, три многострочных блока уже учитывают одновременно ширину и высоту, восемь старых многострочных вызовов остаются в очереди следующих экранов.
- Автоматически проверяются восемь поверхностей: основная панель конструктора, окно атласа, палитра слоёв, рюкзак, семейство предметных окон, HUD, дерево талантов и рыбалка.
- Всего выполняются 2235 атомарных проверок без ошибок. Из них 1452 контракта прогоняют динамические строки рыбалки, пяти вкладок энциклопедии, всех миссий и двадцати талантов на RU/EN/ES/DE/FR/ZH при масштабе 120%.
- Проверка охватывает containment, пересечения, hit-зоны, центрирование иконок, реальные метрики шрифта, safe-padding каталога, кратность сетки атласа, положение номера кадра и минимальный читаемый размер локализованного текста.
- Исправлены два воспроизводимых класса дефектов: текст каталога на резной кромке и номера кадров атласа поверх нижней деревянной рамы.
- Календарные события, характеристики бестиария, идеальный улов и доступная цель разговора больше не обходят локализацию; счётчик уровня в книге талантов вынесен из декоративных морковок.

## Запуск

```bash
tools/Godot.app/Contents/MacOS/Godot --headless --path . --script res://tools/generate_ui_layout_audit.gd
tools/Godot.app/Contents/MacOS/Godot --path . -- --capture-level-editor
tools/Godot.app/Contents/MacOS/Godot --path . -- --capture-level-editor-atlas
tools/Godot.app/Contents/MacOS/Godot --path . -- --capture-fishing-ui
tools/Godot.app/Contents/MacOS/Godot --path . -- --capture-world-map
tools/Godot.app/Contents/MacOS/Godot --path . -- --capture-quest-log
tools/Godot.app/Contents/MacOS/Godot --path . -- --capture-talent-tree
```

После исправления нельзя вручную менять `passed/failed` в JSON: отчёт пересоздаётся командой выше. Новая поверхность сначала добавляется в `UiLayoutAuditSystem`, затем получает тест и контрольный кадр.
