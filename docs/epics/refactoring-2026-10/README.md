## Проблема и первый полезный выпуск

Человек должен находить инструмент по назначению и понимать его зависимости. Сейчас корень tools объединяет QA-сценарии Godot, Python-анализаторы, проверки репозитория, обработку графики, сборку и разовые стенды. Перенос по одному расширению оставил бы инструменты одной подсистемы разбросанными; группируем по ответственности.

В принятой на момент первоначальной постановки main `2fa58d3` непосредственно в tools 750 отслеживаемых файлов: 540 исполняемых исходников и 206 UID. В проверявшемся на тот момент, ещё не принятом head PR №7 `8ef7feae` — 762, из них 548 исходников и 210 UID. JSON и прочие файлы учтены отдельно. Это разные снимки, не сумма двух веток. Точная методика и оба SHA сохранены в ведомости. PR №7 позже принят и влит в main merge-коммитом `7dde012f`; старые измерения не подменяются новым head. REFACTOR-01 составляет актуальную карту принятой main.

Первый выпуск: инвентаризация всех входов/импортов → общая инфраструктура путей и репозиторные команды → тематические QA/asset/build/dev-каталоги → проверка всей цепочки и документация. По завершении в корне tools не более 30 исполняемых исходников; каждый оставшийся публичный вход имеет назначение и причину исключения в README. UID не прячут счётчик исходников. Не создавать сотни совместимых копий старых файлов ради формального уменьшения числа строк в листинге.

## Предлагаемая структура tools

```text
tools/
  README.md
  common/          # пути проекта, общий запуск и чтение протоколов
  quality/         # архитектура, документация, общие проверки
  planning/        # канонические бэклоги и служебный учёт
  assets/          # подготовка и проверка изображений/атласов
  build/           # сборка, экспорт, пакеты
  dev/             # ручные стенды и вспомогательные команды
  qa/
    foliage/
    ground/
    world/
    performance/
    compatibility/
```

Это начальная карта, а не требование создать пустые папки. REFACTOR-01 уточняет границы по реальным импортам. Python/GDScript/профильные контроли одной подсистемы лежат рядом. Движок tools/Godot.app и иные установленные сторонние runtime не перемещать в первом выпуске: их обнаружение и установка — отдельный договор. Разрешены немногочисленные документированные публичные wrappers; внутренние вызовы переходят на новые пути.

## Безопасный перенос

- Выполнять небольшие тематические `git mv`; `.gd` и соответствующий `.gd.uid` переносить вместе, UID не генерировать заново. Сначала один пилотный набор, затем остальные по ведомости.
- Перечислить живые ссылки: Python imports/sys.path, GDScript preload/load/res://, shell/Swift/Node, hooks, Actions, run_tests.sh, Wiki export, команды и ссылки документации. Смена каталога не должна менять смысл запуска.
- Устранить предположение «корень всегда parents[1]» до массового переноса. Проверить запуск из корня и другой cwd, отдельного worktree, каталогов с пробелами и чистого CI. Пути к движку задаются прежним поддерживаемым способом.
- Проверки обходят новые вложенные каталоги рекурсивно; не теряются suites, русская документация методов, ограничения архитектуры, поиск preload и smoke/performance entry points.
- Сохранённые планы, source/config SHA, капсулы, raw, PNG/WebP/MP4 и отвергнутые попытки остаются побайтно прежними. Исторический reader получает исходники из закреплённого Git base/капсулы, а не требует от будущего HEAD старую структуру. Нельзя переподписать старый опыт под новые пути или выключить provenance.
- Поддерживать таблицу «прежний путь → новый путь → живые потребители → проверка». Совместимые входы ограничены принятым публичным списком; временный wrapper содержит причину и условие удаления.
- Механическое перемещение отделять от изменения поведения. Не совмещать переезд, оптимизацию алгоритма, новую механику и исправление стороннего бага в одном коммите.
- Сохранять поведение, форматы CLI/JSON, коды отказа, свежие QA-профили/output, запрещённые перезаписи и бюджеты. Не снижать пороги и не удалять отрицательные контроли ради зелёного gate.

## Приёмка и границы очереди

У каждой карточки свой завершённый результат; аудит не требует уже выполненного переезда. До работ зафиксировать реальные gates принятой базы, после каждого тематического пакета выполнить профильные проверки и общий TESTING.md, для Wiki — её check и браузер. CI и независимое ревью относятся к точному SHA. Старые сохранения, запуск игры, импорт чистого checkout и исторические readers сохраняют работоспособность; аппаратные показатели не подменяются headless.

Эпик не разрешает новых механик/карт, смены движка, переписывания опубликованной истории или удаления чужих веток. Текущая VFOLIAGE-010 не прерывается и не закрывается этим документом. Рефакторинг имеет отдельные ветки/PR; до их принятия карточки не получают done. Существующий курс первой локации сохраняется за пределами прямо заказанной технической очереди.
