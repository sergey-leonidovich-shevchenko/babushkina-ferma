# Пакеты переноса после приёмки REFACTOR-01

[Основание и карта](README.md) · [явная политика](migration-plan.json) · [сильные межсемейные связи](snapshot/cross-family-imports.json).

Это последовательность **внутри будущих карточек**, не новые автоматически начатые задачи. Очередь Team Lead: 02 → 03 → 06; затем маршрут первой локации. 04/05 исполняются только по адресному решению. Каждый пакет — свой содержательный commit; общий PR карточки проходит exact-head ревью. Переезд и логическое изменение не смешиваются.

## REFACTOR-02: опорные условия и пилот

1. **Git-изоляция перед hooks.** Адресно исправить test_shore_kit nested Git по принятому disposable negative control. Снять SHA настоящих config/index до/после; проверить вариант с inherited GIT_* и без него. Не менять родительский config ради прохождения теста. Этот commit предшествует механическим переносам.
2. **Общие пути и импорт.** Только нужные helpers в tools/common; корень по маркерам project.godot/.git, с `.git`-файлом worktree. Один tools/run.py запускает квалифицированные Python-модули; sibling imports становятся квалифицированными. Без глобального PYTHONPATH и сотен wrappers. Для каждого CLI проверить argv, stdout/JSON, exit, FARM_*, cwd и relative-output semantics; временные капсулы не извлекать поверх проекта.
3. **Рекурсивное обнаружение.** До новых вложенных suites привести действующие сканеры к рекурсивному обходу своих явных областей. check_architecture.py сейчас не существует: не придумывать его как пройденный тест. Настоящий shell gate использует нерекурсивные globs; check_documentation исключает tools целиком. README tools добавляется/проверяется адресно, не обходом ignored Godot.app.
4. **Quality, 3 текущих файла.** Переместить check_documentation.py/test_documentation.py и реализацию check_architecture.sh; один shell facade остаётся публичным. Сохранить все нынешние команды/отказы, лимиты и русскую документацию методов. Hooks и Actions продолжают вызывать публичный вход, внутренние команды — новые реализации.
5. **Planning, 11 текущих файлов.** Бэклоги/учёт и их контроли вместе; два Python facade bump_version/task_batch остаются публичными. project_backlog связан с asset_migration, performance — с planning: не скрывать зависимость случайным sys.path. Реальный старый provider пока доступен, import оформляется явно; при 03 обновляется согласованно. Публикация только через PR, task_batch publish не становится обходом.

Сначала новые ignore-правила только для этих каталогов/нужных common-файлов, затем точный git add. Установленный движок и сгенерированные runtime-файлы остаются ignored. Пилот из обычного shell и другой cwd, linked worktree с пробелами, clean checkout/импорт и точный CI. Между этапами сравнить список реально найденных проверок и их отрицательные сценарии, затем полный TESTING.

## REFACTOR-03: тематические пакеты

1. **Assets/build.** Сначала связный блок contracts ↔ migration ↔ build, затем alpha/slicing, authoring, audio. Между contracts и art/camera тоже есть зависимости: использовать явные новые module imports, не копии функций. Не запускать все builders для «проверки help». Старые asset source keys и SHA сохраняются; production остаётся byte-identical.
2. **Camera/performance.** Они взаимно связаны; сначала общий import contract, затем по семейству. Сохраняются два shell facade, один performance_gate.py import/CLI facade с сохранением module identity/присваивания SAMPLER и полный tools/performance_sampler.gd с его UID. Frozen causal test продолжает читать его старые байты. CPU-пороги/180 кадров/форматы evidence не меняются.
3. **Art и ручные стенды.** tools/qa/art и dev/art_review; прямые Wiki exports и документированные CLI обновить. Дизайн-макеты не становятся игровыми ресурсами.
4. **World.** Внутри world — bench/street/board/trade/fence/lamp/order и далее отдельными пакетами. Ground/foliage уже импортируют world, поэтому временный смешанный старый/новый путь должен быть явным и проверенным. Все historical prefix/source namespace отделяются до переезда соответствующего reader.
5. **Ground.** Meadow/edge/road/plaza/garden/decor/seasons небольшими связанными пакетами, каждый collector/verifier/test вместе с его Godot-профилем. Новый collector пишет новый plan/source descriptor; старый reader берёт свою закреплённую капсулу. Отрицательная порча source/capsule/raw по-прежнему отвергается.
6. **Foliage.** Root/UV/wind/contact/speed/recovery/pause/visibility и grass_compare; вложенная группа grass_compare сохраняет внутренние имена. Нативную съёмку не повторять для чистого переезда, но все существующие readers и отрицательные контроли обязательны. Изменение измеряемого поведения потребует уже нового настоящего опыта.
7. **Compatibility.** Совместимые QA действующих систем (не новые механики), по небольшим доменам. tools/water_audit.gd сохраняется целиком как физический исторический anchor. Прямые профили по новым путям и общий Game проверяют сохранение активации.

Каждый исходник Godot перемещается вместе с tracked UID. Для 86 неотслеживаемых UID выполнить отдельный preflight текущего sidecar и canonical clean-import; выбранный стабильный UID добавить поимённо в том же тематическом пакете. Не заменять существующий UID новой генерацией без доказанного основания. Файл, открытый/используемый другим worktree, не удалять из чужой ветки.

## REFACTOR-06 и будущие 04/05

06 сверяет полную карту и фактические исходники: плановый корень 8, бюджет 30, UID отдельны; README показывает общий gate, QA травы и обработку атласа. Отрицательный fixture с новым внутренним файлом в корне должен отказать, разрешённый тематический пройти. Guard не фиксирует навечно 779 файлов. 04/05 остаются невыполненными.

04 сначала переносит только восемь foliage suites либо четыре storage suites, сохраняя фактические nested run и прямые preloads; сравниваются 174 distinct suites,37 верхних запусков, отсутствие потери/дубля и прежние поведенческие проверки. Helpers пока остаются на месте.

05 возможен по одному подтверждённому домену: storage systems/presentation, затем furnace или foliage presentation с согласованным владельцем. Нельзя попутно переписывать алгоритм, RNG, время, кеш или графику. Старый save, штатные переходы, fresh import, UID и serialized resource paths обязательны. Остальные production-каталоги не включены.

## Откат и контроль сохранности

- Перед пакетом сохранить base/head, конкретные старые/новые пути, UID, consumers и список тестов. После — сравнить production/assets и **все старые docs/reports** с закреплённым SHA-манифестом. Нельзя получать зелёный результат переподписью старого плана.
- Откат опубликованного пакета — обычный `git revert <commit>` с восстановлением его ссылок и UID, затем прежние проверки. Никаких force push, reset опубликованной ветки или удаления чужой работы. Непринятый пакет остаётся в том же PR на доработке.
- Каждый этап обновляет таблицу путей и живую документацию, не frozen raw. Исторические ссылки, которым нужен настоящий файл, сохраняются через два заранее названных anchor. Никаких blanket-исключений link/provenance checker.
- Критерий завершения — реальные результаты прежних gates и независимая приёмка точного SHA. Уменьшение числа имён в корне само по себе не доказывает ни сохранение поведения, ни ускорение FPS.
