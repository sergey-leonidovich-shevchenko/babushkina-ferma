# REFACTOR-02 — инфраструктура и пилот tools

Задача выполняется в `codex/refactor-02-maintainable-layout` на принятой базе `d603de591082f19b1a9964eefd8f1d0671d38839`, после завершённой WIKI-003. [План](PLAN.md) и [14 принятых назначений](prepare/baseline.json) ограничивают объём quality/planning; REFACTOR-03 и игровая графика здесь не начинаются.

[Подготовка](prepare/README.md) отделена от будущего механического перемещения. Общая инфраструктура выбирает проект по исходнику, сохраняет argv/stdout/exit и изолирует Git-команды отдельного репозитория от hook-окружения. Законный alternate index текущего hook сохраняется. Красные и исправленные опыты, прежние успешные прогоны и окончательные проверки лежат раздельно.

Рецепт переноса заранее проверяется в disposable полном clone и настоящем linked worktree с пробелами. Это предварительная обкатка, не изменение основной ветки и не приёмка задачи. Каждый опыт хранит команды, источник рецепта, ошибки и подтверждение очистки своего временного каталога. Старые отчёты, планы, капсулы, runtime и UID остаются вне области записи. Два writer CLI дополнительно сравниваются с принятой базой по четырём точным выходным файлам; 320 сценариев остаются запланированными.

Карточка остаётся in_progress без Task-Complete до принятия итогового PR. Каждый head требует своих CI, независимого ревью Tech Lead и решения Team Lead. Проверки headless/свежего импорта не являются новым замером FPS или приёмкой VMAP-003.
