# REFACTOR-02 — подготовка до переносов

Версия 0.0.353; база `d603de591082f19b1a9964eefd8f1d0671d38839`. [Исходные 14 назначений](baseline.json) взяты из принятой ведомости REFACTOR-01. В этом смысловом коммите они остаются по прежним путям: меняются только общие границы поиска проекта, launcher, рекурсивные архитектурные лимиты и адресное Git-окружение. Механический перенос выпускается следующим коммитом той же задачи.

[Настоящий красный опыт](inherited-git-red.json) повторяет sentinel из аудита: унаследованный GIT_DIR перенаправляет nested init в disposable parent и меняет его config. Индекс sentinel сохранён; реальный репозиторий целью не был. Исправление передаёт очищенную копию окружения в nested init/add и readers tracked/historical, а не глобально удаляет окружение hook. Законный alternate index у bump --stage отдельно проверен.

Профильные проверки: 12 сценариев новой инфраструктуры ([журнал](infrastructure-final.txt)), прежние 16 task_batch и 10 shore_kit, восемь исходных planning/документационных команд через launcher. Реальные worktree/коммиты создаются только внутри disposable fixture. PATH/PYTHONPATH родительского процесса не перенастраиваются. Первый launcher не заменял sys.modules['__main__'], поэтому unittest выполнил ноль cases; это не приёмка, журнал сохранён. После alter_sys=True отдельный намеренно падающий unittest обязан выполнить оба cases и вернуть exit 1. Три отказа следующего прогона выявили разницу /var и /private/var в ожиданиях fixture; fixture теперь использует resolve. Ошибка Python 3.9 annotation устранена отложенными аннотациями, отдельная запись сохранена. Первый опыт без core.bare-сентинела и ошибочная shell-команда являются ошибками harness, а не успешными проверками.

Полные architecture/Game/normal/F10 этого кандидата записываются отдельными журналами и gate-exits.json после фактического завершения. Исторические CI принятых PR не выдаются за новые результаты. Старые отчёты, исходные планы, игровые assets/GDScript/UID не меняются; новый общий package marker документирован в tools/README.md. Задача остаётся in_progress без Task-Complete до независимой приёмки итогового PR.

Первый полный кандидат дал architecture 83/1147 и Game 53502/0, normal/F10 по 90/0. После этого дополнительный [красный случай](existing-path-shadow-red.json) показал, что уже присутствующий в PYTHONPATH корень мог оставаться позади чужого пакета tools. prepare_imports теперь явно поднимает собственные пути в начало; обе конфигурации проходят те же 12 cases на Python 3.11 и 3.9. Окончательные полные gates после исправления находятся отдельно в `path-priority/`; исходный полный прогон не перезаписывается и не заменяет проверку нового источника.

В предварительном полном linked worktree рецепт дополнительно проверяет 13-й case пакетного `-m` и публичных import aliases. Первый опыт выявил игнорируемые заново созданные wrappers и ошибочное изменение строкового fixture-import; второй — рекурсивный запуск старого __file__ в task_batch. Ошибки сохранены в `preview/` и `preview-2/`, временные корни удалены; исправления относятся к рецепту будущего механического этапа. Они ещё не применены к основной рабочей копии. Исходники каждого прототипа сохранены как текст в preview-inputs*, чтобы просмотр доказательства не запускал перенос.

Третий предварительный опыт прошёл все 22 команды: 13 граничных cases, 16 task_batch, прежние planning/документационные контроли, публичные входы, четыре точных writer-выхода и свежий headless-импорт Godot с нулём ошибок. Linked worktree остался чистым после импорта; собственный временный корень удалён. [Результат](preview-3/result.json), [команды](preview-3/commands.json), [импорт](preview-3/import-check.json), [очистка](preview-3/cleanup.json). Это предварительная проверка рецепта; основная ветка в этом коммите ещё не перемещает 14 файлов.

Окончательная подготовка 0.0.353 после исправления приоритета путей прошла полный architecture 83/1147, Game 53502/0 и main normal/F10 по 90/0, фактические exit 0 ([интервалы](path-priority/gate-exits.json)). [Сверка сохранности](preserved-files.json) побайтно проверила 410 прежних файлов отчётов Wiki/REFACTOR-01, 798 UID и 13 JSON/архивов планов против Git blobs принятой базы. Версионные metadata — единственное изменение игровой конфигурации; [точная сверка](metadata-scope.json). Остальные шесть карточек REFACTOR и planning state/sources неизменны.

Полные gates выполнены явно до commit/push. Для этого смыслового коммита `--no-verify` предотвращает повторный запуск уже успешных дорогих проверок; версия синхронизирована и проверена, обычный post-commit сохраняется. Это не одобрение PR: после механического коммита обязательны новые итоговые gates/Wiki/CI и независимое ревью точного SHA. Собственная полностью влитая ветка WIKI-003 удалена после проверки ancestry/tip/отсутствия worktree; [учёт очистки](previous-branch-cleanup.json), отдельного нового closeout WIKI-003 нет.
