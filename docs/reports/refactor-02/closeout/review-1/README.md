PR19 остаётся на повторной приёмке; merge и REFACTOR-03 не разрешены.

Регрессии запускают реальный helper в собственном clone и настоящем linked worktree с пробелами. Только намеренно портимые файлы копируются, остальные входы доступны через hard links. Для быстрого fixture Git используется настоящий снимок source index и локальный core.trustctime=false: hard links меняют ctime, но сохраняют inode/mtime/байты. Никаких skip-worktree/assume-unchanged битов не добавляется. Пробный tools-файл имеет обычный H-entry, новый untracked-файл находится в неигнорируемом tools/common. Каждый случай восстанавливает только собственные индексы. Изменения проверяемых файлов действительно проходят через Git, а не через mock.

Первые попытки стенда сохранены и не считаются red/green допуском: `profile-red.*` упёрлась в полный zero-stat scan/таймаут с Git lock; `profile-red-2.*` остановлена на дорогом git add всего снимка до запуска тестов. `profile-red-3.*` выявила изменяемый чужой alternate index старого reader и ошибочно выбранный игнорируемый новый файл; сборщик отчёта ещё не успевал записать результат перед assertion в teardown. Источники каждой версии стенда сохранены отдельно. Финальные сценарии восстанавливают чужие fixture-индексы перед каждым случаем, пишут наблюдения до teardown-проверок и используют неигнорируемый новый файл. Timeout завершает только собственную группу reader/Git.

Профиль: `python3 docs/reports/refactor-02/closeout/review-1/test_scope_git.py -v`. Двенадцать случаев охватывают чистого кандидата/другую cwd, foreign context, tracked/staged/untracked/new-staged edits, config-only overrides, ложный bare config и порчу старого доказательства. Полный tools-бюджет и FPS/VMAP этим не принимаются.
