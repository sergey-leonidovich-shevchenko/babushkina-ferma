**Статус: blocked. Задача не принята.** Подготовлен кандидат дробной камеры и стенд парной съёмки. Нативная приёмка требует разблокированной графической сессии macOS; сейчас ОС сообщает `CGSSessionScreenIsLocked=true`, а тестовое окно остаётся без фокуса. Принятых кадров и роликов **0**. Окончательный выбор по видео, перенос в `main` и `Task-Complete` остаются открытыми.

Исходная `main` — `95475d2b30e9612deac2740c5b7a76267e50a8d4`, приложение 0.0.261. Прежний CameraSystem сохранён без редактирования в [legacy_camera_system.gd](legacy_camera_system.gd). ## Подготовленная запись

Три физических формата: 1152×648, 1920×1080, 2304×1296 на Retina 2×; оба варианта в каждом формате. Сохраняется штатный `canvas_items`, логический холст 1152×648 и единичный UI. `ViewportTexture.get_size()` записывается отдельно и не считается размером Image. Проверяются реальные размеры окна/readback, фокус, метки, стопы, фон, матрица масштаба, обратный указатель и клетка 24×24.

В каждом ролике **две отдельные подготовленные сцены**, по 180 кадров:

1. Медленная диагональ из `(562.25,672.25)` со скоростью 18: пересечение порога следования x=576.
2. Явная смена сцены на кадре 180, старт `(60.25,672.25)`, диагональ к левому физическому пределу x=40. Сохраняются коллизии и скольжение; указатель проверяет край и обе стороны первой границы клеток.

Клавиши D+S и A+S проходят через настоящий игровой маршрутизатор. Координата назначается только перед каждой из двух сцен; это не непрерывный маршрут VBASE-005 и не измерение перехода телепортом. На каждом следующем кадре вручную вызывается **полный GameLoop** с delta 1/60, автоматическая физика отключена, часы/NPC/анимация продвигаются. Вторая сцена явно подписана в видео.

PNG считываются с настоящего GPU, H.264 кодируется после завершения игры без изменения размера. Ожидаемая шкала ролика 60 кадров видео/с не означает 60 FPS приложения: весь набор `performance_eligible=false`. При успешной съёмке сохраняются исходники, SHA256, raw всех 360 кадров, три PNG, декодированный первый кадр, журнал и MP4 каждого случая. Верификатор проверяет разные процессы/профили, весь физический след, независимую формулу камеры и одинаковые физику/указатель между вариантами.

## Наблюдаемое препятствие

[Состояние сессии](session-observation.json), [читающий код](session-probe.swift), [реальный отказ старта](controls/unfocused-start/capture.json) и [журнал](controls/unfocused-start/engine.txt.gz).

Окно и root действительно имели 1152×648, mode=windowed; `focused=false` остановил съёмку **до первого кадра**. Дисплей сообщил 3584×2240, screen scale 2.0, HiDPI=true. Отдельный запуск через macOS LaunchServices также получил `focused=false`. Повторная read-only проверка CGSession показала установленный признак блокировки экрана и завершённый вход в систему. Это препятствие среды для нативного сравнения, а не установленный дефект камеры.

В раннем отказе поле `manual_steps=358` было константой коллектора, а не наблюдённым числом: `frames=[]`, фактически записанных шагов 0. Исходный отказ сохранён без исправления байтов; текущий инструмент вычисляет этот счётчик из записанных шагов. Этот отказ целиком исключён из приёмки.

Первый неполный пакет сохранён в `/private/tmp/farm-quantization-window-rejected-01`, последующие наблюдения — `/private/tmp/farm-quantization-window-observed-02` и `/private/tmp/farm-quantization-launchservices-03`. Они не включены в положительный пакет. При первом headless-подборе старт x=36.25 оказался за действующим пределом x=40; исправлена QA-точка, коллизии игры сохранены. Этот ранний пробный результат остаётся в `/private/tmp/farm-quantization-probe-01`.
