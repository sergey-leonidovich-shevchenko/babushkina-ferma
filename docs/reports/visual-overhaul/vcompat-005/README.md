# VCOMPAT-005 — Коллизии воды при смене графики

Парный сценарий в двух экземплярах `main.tscn` использует движок Godot 4.7.1, viewport 1152×648, масштаб 120%, камеру `(264, 144)`, seed `20261015` и одну фазу воды. Штатный `WorldBackground` применяет обычный профиль, затем обновляет материалы реки и пруда с учётом настройки уменьшенного движения. В headless сценарий открывает готовый для обновления слой вручную, поскольку процесс без GPU не получает кадр, после которого обычно открывается слой.

## Что сравнивается

- Каждый экземпляр загружает копию сохранения [v1-core](../../../../tests/fixtures/saves/v1-core.json). Герой начинает в клетке, затопленной в актуальной геометрии. Штатная миграция переносит его на сушу и сохраняет монеты и инвентарь. Переключение материала и камеры сохраняет полный снимок после загрузки.
- Для штатного запуска обеих сцен используется отдельный `user://`. В контрольном каталоге лежат настройки схемы 1, основной и резервный тестовые слоты. Обе сцены видят чистый профиль, а файлы сохраняют свои байты. После проверки восстанавливается исходный каталог процесса.
- Движение через центр обоих настилов выполняется обычным методом с коллизиями. Реестр воды сохраняет поверхность под настилом. У реки и пруда герой проходит лишь часть пути, остаётся всем телом на сухой стороне и останавливается при следующем шаге. Повтор той же команды с игровым `noclip` доходит до запрошенной координаты. Проверка сухой остановки отклоняет этот результат.
- На мосту и рядом с прудом используется обычная удочка. Проверяются закреплённая точка поплавка вне настила, тип водоёма и расход одной наживки и единицы прочности. Заброс вне радиуса оставляет прежние расходники и состояние `idle`.
- В обоих профилях сравниваются итоговые координаты, игровые события, состояние удочки и полные снимки сохранения.

Профиль с исправлениями ревью прошёл 55 проверок без ошибок в Godot 4.7.1. Исходные проверки топологии, навигации и рыбалки на `e79a3a870eb683e09e4ce3c5dfd02e6ea67e9777` прошли с результатами 576/0, 1750/0 и 1410/0. Профиль и его включение в полный игровой набор проверяются в обязательном GitHub Actions. [PR №65](https://github.com/sergey-leonidovich-shevchenko/babushkina-ferma/pull/65).
