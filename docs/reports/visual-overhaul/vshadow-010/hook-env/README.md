# VSHADOW-010 · изоляция fixture Git внутри настоящего hook

Первый штатный hook учёта прошёл quality (147 файлов, 0 failed steps), но остановился в `test_contract` до завершения architecture и Game. Чистый CI принятого PR №74 не имел окружения Git hook и не воспроизвёл этот дефект. Старое одобрение не применяется к новому исправлению тестов.

Четыре fixture-команды `git init/add/commit/rev-parse` наследовали `GIT_DIR` родительского коммита. Явный `-C` не изолирует их от этих переменных. `git init` изменил общий `core.bare` на `true`, после чего `git add` отказал. [Полный исходный FAIL](first-hook-failure.zip) сохранён без фильтрации; это не успешный gate.

Рабочая настройка адресно возвращена в `false`. [Сверка восстановления](repair.json) подтверждает, что файл config после этой операции равен сохранённому ошибочному файлу с заменой только значения `bare`. HEAD рабочего checkout остался `4cf7b421`, исходного checkout — `7976630c`; refs и незавершённые документы не откатывались. Полного снимка config/index до входа в первый hook не было, поэтому побайтное восстановление всего исходного состояния не заявляется. Повторять отрицательный опыт на рабочем Git запрещено.

Fixture-команды теперь получают установленный `git_environment()`. Проверены остальные Git-вызовы семейства: `contract.git`, экспорт Git-архива и sparse checkout уже очищали окружение. CLI-проверка чтения намеренно получает hostile Git/Python, но её обращения к Git изолируются внутри reader. Производственные скрипты, ресурсы, `contract.py` и все 11 входов нативной съёмки не меняются.

Новая `test_hook_context` создаёт полностью временный родительский repo и настоящую linked worktree с `extensions.worktreeConfig=true`. Настоящий `git commit` вызывает pre-commit и сам устанавливает `GIT_DIR`. Один и тот же test case загружается из принятого старого commit и текущего файла. Setup-команды очищают `GIT_*` и отключают посторонние hooks. Отрицательный runner принимает только помеченную папку системного temp, собственный common Git directory и известный SHA старого/текущего кандидата.

- [Старый код](previous.json): получен реальный FAIL, у временного родителя `bare` меняется с `false` на `true`.
- [Исправленный код](current.json): реальный hook проходит; config, оба index, HEAD/refs и окружение внутри hook совпадают до/после. Сам завершающий внешний commit меняет только свою ветку/index, сохраняя родительские main и index.
- В собственной внутренней fixture сравниваются staged paths/modes/blobs. Её `git diff` вправе обновлять stat-cache после восстановления файлов. Побайтная защита чужого index проверяется новым внешним hook-сценарием, а не подменяется сравнением staged entries.

Два новых сценария и прежние семь контрактных тестов прошли ([регрессия](regression.txt), [контракт](contract.txt)). Они входят в обязательный architecture. [Packing](packing.json) связывает файлы по SHA. Новый код требует полного штатного hook, exact-head CI, независимого ревью и отдельного решения Team Lead; версия приёмки PR №74 и замороженные кадры сохраняются.
