# VBASE-001 · управляемая исходная база

15 октября 2026. Выполнен первый технический этап визуальной переделки: воспроизводимый нативный маршрут, проверка условий и три независимых повтора. Игровая графика, механики и renderer не изменены. Задача родителя OPT-01 не закрывается: полный набор карт, GPU-локализация и бюджет всей игры остаются за ним.

## Результат

Все три прогона получили `VALID_BASELINE`: настоящее окно и framebuffer **1152×648**, режим windowed, VSync enabled, фокус на всех измеряемых кадрах. Каждый процесс прошёл **16 точек за 902 физических шага**, от дома через мост к площади и обратно; игровые часы продвинулись на **15,0333 минуты** (15,0333 секунды симуляции). Позиция в ходе измерения не назначалась: контроллер передавал клавиши штатному обработчику, работали коллизии, NPC, погода, музыка и игровые события.

Порог-кандидат для 60 FPS: p95 ≤18,5 мс, p99 ≤33,333 мс, максимум ≤100 мс. Это индикатор существующего OPT, а не согласованная нижняя аппаратная граница VBASE-002. Валидность базы означает качество протокола, а не выполнение бюджета. Все повторы сохранены, худший не заменён повторным запуском. Длительность каждого интервала взята из монотонных часов между `frame_post_draw`; общая сумма совпадает с полным временем интервала, draw-индексы непрерывны. Метод квантилей общий с OPT (`floor((n−1)×q)`).

Пик draw calls — **171**; счётчик текстур Godot — **689 484 000 байт ≈657,54 MiB**; статическая память процесса по Godot — до **131 864 673 байт ≈125,76 MiB**, включая инструментарий. Перестроений terrain cache во время маршрута — **0** во всех трёх запусках. Эти счётчики не равны RSS/физически занятой VRAM и не доказывают утечку либо конкретное узкое место.

## Паспорт и ограничения

- Исходный runtime: `daeeeecea25819e5c54c715f4c17cda313ce08df`, приложение 0.0.203. SHA256 стенда/анализатора/launcher, проекта и сцены сохранены в [session.json](native/session.json). Инструменты на момент прогона ещё не были закоммичены; их точное содержимое привязано хешами. Поздний автоматический bump версии при публикации не является новой реализацией рендера.
- MacBookPro16,1; Intel Core i7-9750H, 16 GiB, AMD Radeon Pro 5300M. macOS 15.4.1; Godot 4.7.1 stable; Compatibility / OpenGL3. Экран 3584×2240 с масштабом 2; **это размер дисплея, не измеряемого окна**. Фактические значения на каждом кадре — в `condition_groups`.
- Сеть питания AC во всех граничных снимках, Low Power Mode 0. Сведения `pmset` о scheduler/speed limit — 100 и 12 доступных CPU; это не непрерывное измерение температуры.
- Сохранены 15 наиболее активных процессов по `ps` перед/после каждого запуска, без аргументов команд и пользовательских путей. Во втором прогоне фон включал ChatGPT, Chrome helpers, coreaudiod и WindowServer. Разброс p95 значителен. Два снимка не доказывают причинность; **нельзя приписывать второй прогон только игре или только фону**. Чужие приложения не завершались, системное питание не менялось.
- Внутри интервала не снимались PNG, не писались файлы и не запускались другие тесты. До измерения: подготовка окна, 120 настоящих отрисовок с замороженным миром, исходный PNG, ещё 8 отрисовок. После: конечный PNG и JSON. Профиль — новый `Codex-VBASE-001-*` на каждый процесс, настройки/слоты игрока не загружаются; Godot log явно направляется в каталог отчёта ещё командной строкой.
- Начальная камера и карта совпадают, точки проходятся на одинаковых физических шагах. Во время маршрута камера штатно следует за героем. Сид 20261015 и стартовое игровое время 06:00 закреплены; количество отрисованных кадров не фиксируется ради одинакового реального пути.
- Это одна тёплая прогулка по деревне. Холодный старт, 30 карт, бой, шкаф, длительная сессия, физический ввод и другие ОС не приняты. Мировые события и графика не заменены макетом. `Performance.TIME_PROCESS/TIME_PHYSICS_PROCESS` сохранены как движковые мониторы, могут быть с предыдущего обновления; они не используются для атрибуции стоимости кадра CPU/GPU.
- Новый стенд рисует непосредственно в root viewport. Прежний VIS-00 снимал SubViewport 1152×648 внутри полноэкранного окна 3584×2240. Эти результаты **не являются парой до/после оптимизации**; процент ускорения не рассчитывается.

## Исправление протокола

Одного CLI `--windowed --resolution` и раннего `root.size` оказалось недостаточно: при старте проекта macOS завершала полноэкранный переход асинхронно. Сохранён [реальный отказ подготовки](controls/setup-rejected.json): окно и framebuffer 3584×2240 вместо заданных 1152×648. Стенд теперь ждёт стартовый переход, однократно задаёт windowed, отдельно ждёт resize и только затем прогревает сцену. Размеры не исправляются в середине измерения; любое несоответствие отклоняется. Если подготовка всё ещё не успела, отчёт остаётся отказом, а не подгоняется под ожидаемые размеры.

Основание разделения метрик: [Godot DisplayServer.window_get_size](https://docs.godotengine.org/en/stable/classes/class_displayserver.html#class-displayserver-method-window-get-size) возвращает клиентскую область окна в пикселях; [Window.content_scale_size](https://docs.godotengine.org/en/stable/classes/class_window.html#class-window-property-content-scale-size) задаёт виртуальное базовое разрешение. В этом preset масштабирование выключено, фактический readback проверяется до/после отдельно от запроса.

`python3 tools/test_visual_baseline.py`: 11 тестовых методов с положительными и отрицательными вариантами: размер/фокус в середине, readback, headless/pacing, часы мира, пропуск/дубль кадра, сумма интервалов, NaN/Inf/ноль, телепорт/контрольные точки, одиночный рывок, три разных PID/профиля, питание/фон. Анализатор проверяет также одинаковую конфигурацию и питание между повторами. Скриншоты исходного и конечного игровых кадров просмотрены; они подтверждают сцену, а не плавность движения.

## Повторение и следующий шаг

Из корня репозитория, с новым каталогом и без параллельной сборки:

```sh
python3 tools/run_visual_baseline.py --output /private/tmp/farm-vbase-new-run
python3 tools/analyze_visual_baseline.py /private/tmp/farm-vbase-new-run
python3 tools/test_visual_baseline.py
```

Для короткой проверки — `--repeats 1`, результат только `VALID_SINGLE_RUN_ONLY`. Для отрицательного контроля добавить `--fault resize`, `--fault pause` или `--fault focus`; ожидается код 2. Не перезаписывать плохие результаты. На Windows/Linux пока нет адаптера питания/паспортов: `UNAVAILABLE` явно исключает полную сессию из сопоставления. Процесс имеет ограничение 180 с; тайм-аут также считается отказом, а не успешным укороченным маршрутом.

Перед публикацией выполняются обязательные `tools/check_architecture.sh` и `./run_tests.sh`; итог фиксируется в карточке. Следующие художественные работы остаются заблокированы VBASE-003/004: сначала закрепить точки камеры и статический эталон деревни, затем VART-001 с двумя вариантами. VBASE-002 отдельно определит поддерживаемое оборудование. Откат этой задачи — убрать инструменты и документационный gate; пользовательские сохранения и игровые ресурсы миграции не требуют.
