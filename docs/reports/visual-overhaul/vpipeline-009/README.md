# VPIPELINE-009 — безопасная миграция графических файлов

Основание — `1621d49502cd244c1036168f9d235561b708b33a`, игра 0.0.245. Подготовлены порядок перехода, владельцы всех 29 мировых семейств, граф потенциальных потребителей и изолированный пример переноса с откатом. **Рабочие PNG, игровые скрипты, форматы сохранений и пользовательские черновики этой задачей не менялись.** Адаптер путей показан только в диагностической копии.

## Проверенные входы

В [снимке](inventory.json) **2760 runtime-файлов**, **1167 кодовых/метаданных файлов-потребителей**, **14 497 потенциальных связей** literal/template/prefix/UID и **127 вычисляемых загрузок**, требующих разбора владельцем. У UID импортированных растров из `.import` дубликатов нет; собственные UID скриптов/`.tres`/бинарных ресурсов этим индексом не объявляются исчерпывающе разрешёнными. Это не число живых текстур или выполненных загрузок. Ввод редактора, пользовательские слоты, внешние паки и любая неразрешённая динамика не становятся проверенными из-за отсутствия строки в графе.

Снимок строится по tracked-дереву исходного commit, учитывает `.gdignore` и политику VPIPELINE-001. Проверка заново выводит граф из привязанных исходников, сверяет его полноту, хеши, UID и вычисляемые места. Исторические файлы читаются из read-only Git baseline при будущих изменениях; новые согласованные рисунки не обязаны сохранять старые байты. Gate сам сеть не использует. CI отдельно получает исходный commit через существующий шаг загрузки baseline; тест shallow clone воспроизводит необходимость этого fetch на локальном временном репозитории.

## План и владельцы

[План](plan.json) связывает **29 семейств / 238 деклараций / 236 различных файлов** с решениями VART-009 по ID, а не позиции в массиве. У общего файла один ведущий эпик и список пересекающихся семейств. Художественная ответственность остаётся у VGROUND/VPROP/VSHORE/VTREE/VPLANT/VACTOR/VBUILD/VFX; инфраструктурный владелец — OPT-03. WATER сохраняет единственную геометрию, VEDITOR — пользовательский формат, VCOMPAT — старые слоты и откат. Родительские эпики не закрыты.

Каждое семейство проходит одну последовательность:

1. **Снимок.** Зафиксировать ID, конкретных читателей, текущие параметры импорта, UID, области, опоры, footprint, кадры и состояние. Не переносить всю игру одной партией.
2. **Staging.** Мастер хранить под барьером исходников; новый runtime-файл добавлять рядом с прежним. Для нового PNG получить свой UID, сохранить intent, mip/filter и альфу. Старый UID не копировать новому файлу.
3. **Регистрация.** Сохранить content/resource ID, направления и смысл качества. Обновить центральный паспорт и конкретных потребителей; старое имя PNG не объявлять устойчивым ID.
4. **Производные данные.** Согласованно пересобрать подготовленные пиксели, индекс иконок 64/160, страницы 64/32/16/8 с полями и крупные превью. Каталоги проверяют provider/path/tint/source hash: совпадение картинки не отменяет смену ключа. Холодный/повторный вход и бюджет памяти проверяются отдельно под OPT-03/VPERF.
5. **Совместимость.** Разрешать старый путь до загрузки текстуры; сохранять raw-пути, UID, метаданные, фильтр, source rect и пользовательские коллизии. Черновик v6, опубликованный уровень, избранное, undo/redo и отдельные импортированные документы имеют разные читатели. Для иной геометрии нужен явный преобразователь версии с атомарной записью и резервной копией.
6. **Wiki.** Пересобрать каталог и проверить ID игровых статей, связи, направления, области, опоры и физическое наличие иллюстраций. Новая статья руководства допускается; игровые ссылки не переименовываются вслед за PNG.
7. **Сравнение.** Выполнить VPIPELINE-001…008, весь TESTING.md, настоящие пары при одной камере и состояния холодного/тёплого входа. Стоимость и приёмка нового арта — отдельные ворота MVP.
8. **Откат.** Восстановить паспорт, прежний маршрут, `.import`/UID и согласованные производные индексы. Обычный revert вместо переписывания опубликованной истории; материалы и доказательства сохранять до приёмки.
9. **Удаление.** Отдельная операция владельца после приёмки всех читателей, старых внешних документов, экспортированного пакета, холодного старта и отката. Отсутствие literal-ссылки, успешный кадр или нулевое число найденных дубликатов не разрешают удаление.

Текущие ворота удаления: **VEDITOR-001/002/004/008, VCOMPAT-002/010 и VPIPELINE-010**. Эта задача не реализует их вместо владельцев. План не содержит production-операций или общего разрешения массово переименовать/удалить ресурсы.

## Настоящий изолированный пример

Скопированы **107 literal-зависимостей / 178 файлов с импортами**, около 28 МБ, включая настоящие VisualResourceCatalog, LevelEditorAssetCatalogSystem, LevelEditorDocumentStore и их зависимости. [Подписи входов](fixture-sources.json). Запускается отдельный Godot-проект; Game и симуляция не создаются, слоты игрока не читаются. Входной документ — специально созданный черновик v6 с тремя ракурсами дубового стола, заметками, ID объектов, source rect и footprint.

Проверены пять последовательных состояний одного проекта, каждое в новом процессе и новом `Codex-VPIPELINE-009-*`:

| Состояние | Результат |
|---|---|
| baseline | Старый каталог и настоящий загрузчик черновика проходят |
| dual | Новые PNG и собственные UID, прежние пути сохранены; прототип адаптера сохраняет профили F12 |
| unadapted | PNG ещё существуют, но адаптер отсутствует: три старых пути теряют профиль и адресный фильтр |
| retired | Удалены только старые PNG копии: настоящий валидатор находит три отсутствующих спрайта |
| rollback | Восстановлены старый каталог, PNG и прежние `.import`/UID; staging-файлы убраны |

Это **rename-only** тех же пикселей. Новый рисунок с другой областью/опорой, произвольный уровень, размещение в полноценной сцене, pack/export и производительность этим примером не принимаются. Старые материалы и прототип адаптера остаются вне рабочей игры. Сам прототип не является готовым production alias resolver.

## Нативные доказательства

**10 GPU-кадров**, два фона, фиксированный SubViewport **1152×648**, Godot 4.7.1 Compatibility/opengl3, AMD Radeon Pro 5300M. Верхний ряд использует новый путь через каталог; нижний — старый документ F12, настоящий профиль и sampling. Размер окна не выдаётся за target. Текстуры удерживаются владельцем стенда до readback, чтобы потеря временной ссылки не подменяла проверку совместимости.

![Перенос с адаптером: каталог и сохранённый черновик совпадают](native/dual/dark.png)

- `dual` и `rollback` совпали с baseline на обоих фонах целиком: **0 отличающихся пикселей**.
- Без адаптера верхний ряд остаётся прежним; нижний отличается на **36 257 / 34 649** пикселей. PNG существуют, но старый путь больше не получает тот же фильтр.
- При преждевременном удалении верхний ряд прежний, нижний отличается на **43 360 / 43 364** пикселя; три старых пути не существуют, документ невалиден.
- Все три новых UID отличаются от всех прежних, старые UID сохранены при dual и восстановлены при rollback. Пиксели, смысловой ID, три ракурса, геометрия, заметки и остальные поля документа не изменены. Невалидность retired — ожидаемый отрицательный контроль, без ошибки движка.

## Повторение

```sh
python3 tools/asset_migration.py
python3 tools/test_asset_migration.py
python3 tools/test_migration_proof.py
```

16 сценариев плана/графа и 6 сценариев порчи доказательств используют только временные копии. Проверяют потерянную семью/ссылку, UID, исходники, динамику, смену ID/footprint, неверный порядок, выход из папки, shallow checkout, изменённый пиксель, замену отрицательного контроля, заметки документа, ракурс, target, Wiki и ложную запись «production не менялся». Даже пересчитанные SHA не принимают нарушенные смысловые условия.

Для отдельного нового стенда (путь должен быть новым и вне репозитория):

```python
import sys
from pathlib import Path
sys.path.insert(0, 'tools')
from asset_migration import BASE
from migration_fixture import create, phase
create(Path.cwd(), Path('/private/tmp/migration-new'), baseline=BASE)
# Перед следующим состоянием: phase(Path('/private/tmp/migration-new'), 'dual')
# Порядок: baseline → dual → unadapted → retired → rollback.
```

После каждого состояния выполнить Godot `--headless --editor --path /private/tmp/migration-new --quit`, затем запустить `--path /private/tmp/migration-new --windowed --resolution 1152x648 --rendering-method gl_compatibility --rendering-driver opengl3 --script res://tools/migration_capture.gd` с **новыми** `VMIGRATION_OUTPUT` и `VMIGRATION_PROFILE=Codex-VPIPELINE-009-…`. Для GPU-кадров нужен настоящий дисплей. Создание стенда не запускает shell или игру автоматически. Нормальная проверка не пересоздаёт исторические доказательства и не выполняет Git fetch.

В отчёте нет вывода об FPS, экономии памяти или завершённой массовой миграции. Следующая VPIPELINE-010 занимается происхождением, размерами и оценкой памяти файлов.
