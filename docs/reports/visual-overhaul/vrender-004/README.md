## Подготовленный контракт

`scripts/presentation/object_draw_command.gd` создаёт версионированный read-only Dictionary. Внутри только значения и общие ссылки на Texture2D/Material; Node, игрок, callback и очередь мира не сохраняются.

| Поле | Значение и владелец |
| --- | --- |
| `version`, `id`, `world`, `space` | v1, устойчивый ID объекта, ID мира, только `world` |
| `anchor` | Нижняя опора в мировых пикселях; камера ещё не вычтена |
| `bounds` | Прямоугольник рисунка в тех же координатах, отдельно от коллизии |
| `texture`, `source` | Общая текстура и область в её пикселях; у AtlasTexture — относительно самого ресурса |
| `local_uv` | Канонический прямоугольник 0…1 всего объекта, отдельно от региона атласа |
| `material`, `modulate` | Явный null/CanvasItemMaterial/CanvasItem ShaderMaterial и цвет/альфа объекта |
| `layer` | `ground`, `behind_actors`, `actors` или `foreground` |

![Поля и два исхода команды](contract.svg)

Все ключи обязательны, неизвестные поля отклоняются. Неверные типы, версия, экранные координаты, пустые ID, отрицательные/нечисловые границы, внешний source, испорченный UV, отсутствующая текстура, 3D-материал, ShaderMaterial без canvas-item shader, неверная альфа отвергаются до первого draw. Снимок не связан с последующими изменениями исходного словаря. Общие ресурсы намеренно не дублируются: read-only словарь не превращает внешний Material/Texture2D в глубоко неизменяемый ресурс; их изменением управляет владелец, replay ничего в них не пишет.

`object_draw_replay.gd` проверяет текущий мир/фазу и точную идентичность собственного материала CanvasItem; `use_parent_material` не допускается. Он не подстраивает под пакет общий root, HUD, камеру или материал родителя. После проверки вызывается тот же `draw_texture_rect` / `draw_texture_rect_region`; на отказе прежний callback вызывается ровно один раз, либо возвращается `rejected`, если callback отсутствует. Восстановление после ошибки внутри чужого callback или асинхронного GPU-сбоя этим не обещается.

`world_workbench_visual_system.command()` описывает существующий верстак: 0 — вниз, 1 — влево, 3 — вправо. Тело прежнего production `draw()` сохранено точно, обычная игра продолжает вызывать его. Пакеты не создаются покадрово в обычном маршруте. Новых runtime-узлов, viewport, таймеров, CPU-readback или глобальной очереди нет.

Единственный новый вызов `draw_texture_rect_region` зарегистрирован в `tools/slice_policy.json`: источник ограничивается фактическим размером Texture2D до рисования, три ресурса верстака уже входят в общий аудит атласов. Эта регистрация сохраняет полный охват мест нарезки, но не заменяет ожидающую нативную приёмку replay.

## Граница с последующими задачами

Это описание одной осевой картинки и проверяемый replay, **не включённый новый проход**. VRENDER-005 включает выбранный участок feature flag; VRENDER-006 отвечает за общую сортировку и равную опору; VRENDER-007 — за отделение перил. Время/позиции и несколько viewport остаются VRENDER-008/009. Сохранённый `local_uv` — семантика вершины команды: существующие draw API сохраняют штатный UV текстуры/атласа. Отдельное shader-атрибутное связывание локального UV и новый GPU-batching здесь не включены и нативно не приняты.

## Выполненные проверки

`tools/object_command_review.gd`: **41 утверждение / 0 ошибок**. Три настоящих ракурса, реальные AtlasTexture и пропорции, независимость от коллизионного следа, копия словаря, типы/материалы/цвет/UV, чужая фаза/карта, ровно один fallback, полный save и физическая позиция героя. 1 200 прежних правил навигации/вспашки и восемь swept-движений у мостов сохранены.

`tools/test_object_command.py`: **10 сценариев / 0 ошибок**. Это явно синтетические schema fixtures для валидатора доказательств, а не нативные кадры. Проверены ложные заявления live-pass/FPS, отсутствие случая/фокуса/callback, изменение инвентаря, утечка материала, неверный UV/ракурс, повтор fallback, изменение трансформации и даже скрытого RGB прозрачного пикселя. Незавершённый архив никогда не принимается. Эти parser-тесты входят в architecture; сам native verifier будет обязательным gate только после принятой серии, чтобы незавершённая работа не делала весь проект постоянно красным.

`contract.json` — явный headless-экспорт трёх настоящих дескрипторов, не доказательство GPU. `review.txt`, `python-check.txt` содержат фактические результаты. Общий игровой набор, architecture и Wiki должны быть выполнены перед промежуточным commit; их журнал сохраняется отдельно. Зелёный общий набор не закрывает нативную приёмку этой карточки.

## Нативная проверка, которую нужно завершить

`tools/object_command_capture.gd` сохраняет девять пар обычной сцены: герой/настоящая яблоня сзади и спереди, куст, мост/прежние перила, ручная пауза через обработчик Escape, непрозрачное хранилище и действительный вход/выход дома. Проверяются прежний HUD, материалы, полный save и настоящие draw callbacks при одной камере. Строится дескриптор, но production-pass остаётся выключен.

Дополнительный **изолированный QA SubViewport 256×224** сравнивает старые API с replay: три верстака, регион атласа дерева, частичная альфа, отдельный canvas-item shader; пять отказов — чужой материал, source за границей, чужой мир, чужая фаза, отсутствующая текстура. Каждый отказ должен дать точное прежнее изображение и один вызов fallback. Этот QA-узел создаётся отдельно от игры и удаляется после серии; его существование не означает, что production получил дополнительный viewport. Размеры региона дерева — диагностический quad, не новый игровой ресурс.

План серии: два окна 1152×648 / 1280×720, 120% первой карты; ожидаемые 80 PNG и 248 draw — **план, не пройденный результат**.
