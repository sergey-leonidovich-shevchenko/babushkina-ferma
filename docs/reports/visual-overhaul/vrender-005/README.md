# VRENDER-005 — один выбранный проход

В обычной первой карте включён **один проход тела существующей доски объявлений**: объект `(648,576)`, нижняя опора `(648,600)`, фаза `behind_actors`. Его целый рисунок находится внутри эталонной области `(240,312,960,576)`. Новый путь использует принятый контракт `ObjectDrawCommand` и неизменённый `ObjectDrawReplay`; изображение и геометрия остаются прежними.

Это техническое включение выбранного прохода. В задаче нет нового рисунка, нового общего renderer, сортировки всех акторов/растений, shader-UV, ветра, воды или приёмки всей карты. VRENDER-006/008, живой пилот и VMAP-003 остаются отдельными этапами.

## Включение и откат

`scripts/presentation/pilot_object_pass.gd` разрешает только указанную доску, первую карту, прежнюю заднюю фазу и обычный игровой режим. Редактор F12, передний проход той же доски, вторая доска и остальные предметы сохраняют старый callback. В `VillagePropRenderer` изменён только вызов тела доски; прежние culling, тень, порог перекрытия, порядок вызовов и остальные ветки не изменены. Верификатор восстанавливает этот единственный допустимый diff из Git-базы и сверяет точный архив исходников.

По умолчанию флаг включён. `game.set_meta("pilot_object_pass_enabled",false)` возвращает старый путь; `remove_meta` возвращает принятый default-on. Это временная metadata, не поле save или настройки игрока. Небулевое значение отключает проход. Для остальных карт renderer досок первой карты вообще не вызывается.

Новый путь не меняет материал полотна и его родителя. Чужой материал, наследуемый материал, неверный source, мир, фаза или отсутствующий ресурс отвергаются до рисования; прежний callback вызывается ровно один раз. Прежний `Board.draw` сохраняет собственный запасной PNG. Callback живёт только во время вызова, не попадает в кеш.

## Данные и стоимость

Кеш содержит максимум три read-only команды для принятых ракурсов. В штатном вызове используется передний вид и создаётся одна команда. Камера ещё не вычтена; нижняя опора, bounds, source, texture, null-material, modulate и local UV берутся из реального ресурса. Node, игра, callback, очередь и положение героя не удерживаются. Повторные draw не конструируют пакет заново. Это не обещание ускорения: измерение цены остаётся VPERF.

Диагностика действует только при явном QA-ключе `pilot_object_pass_trace`, создаваемом тестовым observer. Обычная игра его не создаёт и не выделяет диагностических массивов. Даже без потребителя массив ограничен восемью записями; QA сбрасывает его на каждый настоящий callback. Нативные данные записывают исход `command/legacy/fallback`, фактическое число вызовов старого callback, размер кеша и счётчик построений. Все 33 профильных условия проверяют ограничение области, три команды, флаг, наследование материала, атомарный отказ, полный save и 1200 правил движения/вспашки с восемью движениями у мостов.

## Нативная проверка

База Git, точные входы и SHA256 находятся в `native/before/source.json` и `native/after/source.json`. Исходная серия снята **до подключения** адаптера. После сняты выключенный/включённый флаг и отдельный default-on. В обоих нативных окнах 1152×648 и 1280×720 фактический логический canvas1152×648, первая карта 120%; все 136 кадров имели фокус. Новых production-узлов или render targets в код не добавлено.

На окно:23 исходных PNG,45 новых,272 настоящих production draw. Всего **136PNG / 544callbacks**.90 полных RGBA-сравнений совпали побайтно: исходная ветка/выключенный флаг и выключенный/включённый флаг. Проверяется каждый канал, включая скрытый RGB; допусков или масок нет.

Случаи: герой перед/за/по бокам доски, вторая доска вне области, настоящее дерево с двух сторон, ягодный куст, оба моста, Escape-пауза, непрозрачное хранилище, настоящий F12, вход дома, реальный переход в соседний рынок/возврат, шесть отказов и default-on. Полные snapshots, игрок, камера, UI-состояния и материалы совпали. На каждом размере записаны 32 успешных выполнения команды,92 прежних пути и 24 реальных fallback. Передний план остался прежним; на другой карте и под непрозрачным UI новый проход не вызывается.

Пауза здесь — неподвижный экран и сохранность команды; физическое прохождение маршрута, анимация и FPS не заявляются. Временная порча приватного кеша используется только в QA для отказов и после каждого случая удаляется. В обычном маршруте кеш не сбрасывается покадрово. Рост `cache_builds` между QA-случаями после этих принудительных сбросов не выдаётся за обычную загрузку.

16Python-сценариев портят копии настоящего evidence: потеря фокуса, размер, отсутствие/повтор случая, мутация save, ложный флаг/default, утечка материала, разрастание кеша, построение пакета каждый кадр, выход команды за область/фазу, двойной fallback, отсутствие реального default-on и порча RGBA. Исторические данные не перезаписываются. Новый верификатор и тесты входят в обязательный architecture gate.

## Отклонённые попытки и воспроизведение

Первый исходный QA-прогон отклонён: F12 ошибочно доставлялся в поздний `_unhandled_input`, хотя существующий редактор обрабатывает его в раннем `_input`. Исправлен только capture-скрипт, обе исходные серии пересняты полностью. Профиль сначала отклонил неявный тип в тесте, затем выявил ошибку чтения отсутствующей metadata через null-default; нормальный путь исправлен на явную проверку наличия ключа. Серия после подключения снималась только после чистых 33/0 без ERROR движка. Непринятые результаты остались в игнорируемом `tmp`, обычный Godot пользователя не закрывался.

`tools/pilot_pass_review.gd`, `python3 tools/pilot_pass_verify.py`, `python3 tools/test_pilot_pass.py`. Повторная исходная серия требует Git-базу и соответствующий QA-overlay из `native/before/inputs`; текущий renderer не выдаётся за старую ветку. Коллектор требует свежую папку, собственный `Codex-VRENDER-005-*` и реальный дисплей. Данные точного текущего прогона сохраняются с исходниками, а не дополняются кусками прошлых попыток.

Откат функции — временно выключить флаг либо отдельный revert commit. Формат save, коллизии, HUD и другие карты не мигрируются. Общий gate, игровой набор, Wiki и браузер фиксируются в `completion.json` только после фактического выполнения. Этот результат не закрывает новую сортировку VRENDER-006, живой пилот VRELEASE-003 или производительность VRELEASE-004.
