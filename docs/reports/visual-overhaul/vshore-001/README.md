# VSHORE-001 — комплект низкого берега

[Витрина Wiki](../../../../wiki/articles/shore-kit.md) · [Паспорт](profile.json) · [Источники](source.json) · [Нативная съёмка](native/capture.json).

Выбраны низкий камень для деревни и уже принятая земля VART-008 для природных участков. Решение принято самостоятельно по AGENTS.md; новый выбор A/B не запрашивался. Направление задаёт B из исходного референса набережной, отдельные части не вырезались из фотографии всей карты.

Встроенный imagegen подготовил каменный мастер v1, два последовательных исправления v2/v3 и перерисованный широкий настил v1/v2. Все промпты и исходники сохранены в [masters](masters/); выбран v3 камня и v2 настила. Два ранних каменных листа повторяли стороны, первый широкий настил оставался слишком узким. Это отклонённые источники, не игровые ресурсы. Нарезка Godot сохраняет каждый исходный пиксель, альфу и целые координаты; растяжения по отдельной оси и программной перекраски нет.

## Результат

- 16 новых береговых частей: четыре прямые стороны, восемь угловых этюдов, два торца, два перехода камень/земля.
- Две части нового настила, собранные по швам досок с общим масштабом. По прямой просьбе пользователя проход расширен 48 → 72 мира, основание 192×72; края на сетке 24, перила раздвинуты. Три средние доски большого исходника пропущены, чтобы сохранить длину пролёта, без сжатия рисунка.
- 11 переиспользованных частей VART-008: четыре земляных края, четыре части моста и три материала. Итого 29 экспортированных PNG.
- 11 неподвижных GPU-кадров: два листа × три фона, узкий мост, земля/камень при общей камере, герой на мосту и сетка. Каждый неподвижный readback повторён побайтно.
- 120 нативных кадров дробного движения камеры, четыре секунды H.264 1152×648. В Git сохранены видео, полный список подписей и три исходных PNG-свидетеля; остальные PNG остаются временным выводом съёмки. Это не offline-проверка всех исходных пикселей каждого кадра видео.

База — `333037d769dfe6fed8cc13c3e3c46ac9e3dda888` / 0.0.273 плюс точные новые файлы по SHA в capture.json. Сравнения выполнены в одном изолированном стенде: framebuffer 1152×648, поле 960×540, zoom 1.2, камера `[0,0]`, одна неподвижная поза героя, день/ясно без симуляции. Обычная игра и слоты пользователя не загружаются. Пара «узкий/широкий» меняет только конструкцию мостового образца; пара «земля/камень» использует один широкий мост.

Первая проба ошибочно показала весь лист трёх поз героя вместо первой области 192×192; [отклонённый кадр](revisions/hero-region-rejected.png) и исходный код сохранены отдельно. В итоговом коллекторе выбирается ровно первый регион, не растянутый лист. [Ранний узкий мост](revisions/bridge-before.png) сохранён до просьбы о расширении; итоговое сравнение переснято на окончательном коллекторе.

## Проверки

`python3 tools/shore_kit.py` сверяет мастера/промпты, 29 точных вырезок, поля силуэта камня, три фона, одинаковую камеру, полный сдвиг и три свидетеля движения, видео и WATER-протокол. Девять сценариев `tools/test_shore_kit.py` портят только временные копии: потеря торца, дробный регион, поворот света, подмена PNG, возврат узкого моста, headless/FPS, неподвижная траектория, испорченный свидетель и полный положительный комплект. Это проверка данных и доказательств, не автоматическая оценка красоты и не новый runtime-импорт.

`shore_kit_review.gd` запускает прежние WaterTopology/Navigation/Fishing/Visual suites в `Codex-VSHORE-001-Tests`: **845 passed, 0 failed**, без ошибок движка. [Журнал](water-review.log) и [подписи источников](water-review.json) сохраняют точный исторический контекст. Общие WATER-исходники проверяются по Git-базе, поэтому этот отчёт не замораживает дальнейшую разработку воды. Текущая регрессия проекта дополнительно обязательна перед каждым commit по TESTING.md.

```sh
python3 tools/shore_kit.py
python3 tools/test_shore_kit.py
tools/Godot.app/Contents/MacOS/Godot --headless --path . --script res://tools/shore_kit_review.gd
```

Повторная графическая съёмка: `shore_kit_capture.gd -- --output=<новый каталог> --profile=Codex-VSHORE-001-new` с оконным Godot / Compatibility и настоящим дисплеем. Коллектор отказывается перезаписывать output или работать headless. Затем штатный `encode_coordinate_video.swift <frames> <новый mp4> 30 6000000`. Все текстуры создаются до draw, загрузок внутри draw нет. 35 065 920 байт Image с mipmaps — только изображения этого стенда, не полная память игры; fixed-clock/readback не измеряет FPS.

## Открытые владельцы и откат

Полная таблица наружных/внутренних соседств, production-стыки и автоподбор — VSHORE-003 / WATER-04. Дно и поверхность — VSHORE-002/005. Этот горизонтальный мост не заменяет физический вертикальный 96×192 в первом пилоте: для него нужны отдельные части и согласование подходов, без вращения освещённого PNG. Приёмка новой карты, навигации, старого слота, нагрузки и всех водных контекстов остаётся открытой у прежних владельцев. WATER-02 автоматически не закрывается: образ поверхности и reduced motion ещё не принят; ожидание выбора берегов больше не требуется.

Мастера/макеты остаются под `.gdignore`, вне `assets/game`; остальные карты и механики не изменены. Откат — revert этого commit и пересборка Wiki; откат графической миграции и сохранений этим не проверяется. Итог браузера и обязательных gate фиксирует [acceptance.json](acceptance.json).
