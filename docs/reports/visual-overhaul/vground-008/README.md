# VGROUND-008 — ограничения процедурного декора

Задача ограничена первой `overworld`. База — `c9ae970781fae8d1aab95644873668036b5c3011`, версия 0.0.287. Новая механика и другие карты не добавлены. [Карточка](../../../epics/visual-overhaul-2026-10/epics/vground.md#vground-008).

## Что действительно изменилось

Аудит обнаружил, что обычная модульная сцена первой карты использует ручные цветы и акценты. Старый `WorldBackground.draw_meadow_texture()` с детерминированным посевом не имеет production-вызовов. Ограничитель подключён именно к этому запасному методу; новая трава в обычную сцену не добавлена. Вручную расставленные цветы после его вызова по-прежнему рисуются прежним циклом.

`VillageDecorationRules` читает реальные двери/фасады, службы, дороги и выходные ветви, грядки/калитки/загоны, мосты и ручные размещения. Это 161 зона плюс точные полигоны реки/пруда. Проверяется весь прямоугольник с запасом 4, включая воду между сухими углами. Настилы мостов исключены независимо от их проходимости.

`plan(candidates, manual)` принимает не более 512 кандидатов и 512 дополнительных ручных прямоугольников. Результаты независимы от входов; испорченный кандидат атомарно отклоняет план. Невалидная геометрия и ручные зоны закрывают доступ. Будущий авторский посев обязан передавать актуальные ручные зоны; автоматическая интеграция произвольных F12-документов не сделана. Встроенные 286 кандидатов сохраняют исходные порядок и координаты, принимаются 86 / отклоняются 200. Кеш единственный, RNG/узлы/таймеры отсутствуют. Карты вне `overworld` не затронуты.

## Проверка

- `tools/decoration_review.gd`: 47 / 0; полный snapshot, независимые входы/кеш, точная вода, ручной приоритет, 1 200 правил земли и восемь настоящих движений у мостов.
- `tools/decoration_collect.py`: новые изолированные QA-профили и точный архив источников до запуска; два физических окна 1152×648 и 1280×720, логические 1152×648, масштаб 120%. Обычный Godot не закрывается; статическое сосуществование явно записано, не принято за FPS.
- 13 случаев × четыре режима × два окна = 104 полных кадра / 416 полных снимков вокруг production draw. Ещё четыре прозрачных листа посева 2400×1368 = всего 108 PNG.
- `control-before/after` — обычная сцена без диагностического слоя; `before/after` — настоящий прежний посев без/с ограничителем. Дверь, службы, огород, оба моста, поворот, тупик, четыре календарных сезона, дождь, настоящий вход/выход дома. Симуляция остановлена.
- `tools/decoration_verify.py` самостоятельно пересекает прямоугольники и рёбра водных полигонов, сверяет весь план, полные состояния/геометрию/очередь draw, архивы/SHA/Git-базу. 10 ясных контрольных пар каждого окна точны; оставшийся диагностический рисунок укладывается только в принятые следы. Полноразмерный прозрачный лист сохраняет разрешённые травинки побайтно и удаляет запрещённые.
- Дождь использует `Time.get_ticks_msec()`. Его пиксели не объявляются равными: проверяются полный snapshot и геометрия, точный фильтр доказан независимым прозрачным листом. В принятой полной серии A дождь продолжается также в доме и после возврата: три случая каждого окна принимают только snapshot/геометрию. Первоначальный критерий равенства дождя признан неверным; сырые A-данные не изменялись. Повтор B остановился после двух кадров без финального JSON, C — по 180-секундному таймауту без новых callbacks; причины неизвестны, оба не приняты. Нулевой exit сам по себе не принят. [Протокол и незавершённые попытки](sampling-notes.json); неполные серии остаются в игнорируемом `tmp/`.
- `tools/test_decoration_rules.py`: десять положительных/отрицательных сценариев, включая подмену обычного пикселя, полного save, окна/фокуса/масштаба, категорий, числа кандидатов, архива и ложной производительности. Порча только временных копий.

Общий игровой gate, architecture, Wiki и браузер фиксируются в `completion.json` после реального прохождения. Новые runtime bitmap-ресурсы не нужны. Статичные изображения не принимают живую стоимость кадра, GPU-время, RSS/VRAM, сезонный снег или всю первую карту VMAP-003. Откат — возврат старого цикла в запасном методе либо отдельный revert; save-миграции нет.
