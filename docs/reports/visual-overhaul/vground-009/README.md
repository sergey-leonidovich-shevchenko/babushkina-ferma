# VGROUND-009 — локальная ревизия покрытия

База `b3c847f2812e4d7c245fb69f751a670725e7236d`, версия 0.0.288. [Карточка](../../../epics/visual-overhaul-2026-10/epics/vground.md#vground-009) ограничена первой `overworld`; это инженерная работа, не новый рисунок и не механика.

## Аудит и изменение

Полив уже менял только текущую землю и контакты ближайших клеток, без пересборки фона. Но `set_soft_garden()` всегда вызывал полное обновление кеша 2400×1368. Теперь он инвалидирует только прежний огород `(144,816,288,240)` через `invalidate_terrain_rect()`. Общий API принимает и произвольный ограниченный участок первой карты; подключение всех инструментов F12 остаётся у редакторского владельца.

В существующий SubViewport добавлены два постоянных узла: Control с `clip_contents` и прозрачная очистка с `blend_disabled`. Полное обновление использует прежний clear; локальное — `CLEAR_MODE_NEVER`, очистку и рисунок только внутри отсечения. Большая текстура остаётся той же, CPU-readback в production отсутствует. Мировые координаты и UV не сдвигаются: смещение контейнера компенсировано у terrain canvas. Основа, вырезы воды и перекрытие сохраняют порядок. Основание: [SubViewport clear/update](https://docs.godotengine.org/en/stable/classes/class_subviewport.html#class-subviewport-property-render-target-clear-mode), [Control.clip_contents](https://docs.godotengine.org/en/stable/classes/class_control.html#class-control-property-clip-contents); работоспособность подтверждается GPU-кадрами, не только документацией.

Реестр ревизий ограничен 60 номерами секций 256. Очередь — 32 ожидающих прямоугольника плюс один активный. Пересечения объединяются до устойчивого результата; далёкие области не превращаются в один большой прямоугольник. Запрос в активную область не теряется. Некорректный ввод отвергается без мутации. Переполнение явно возвращает полную перерисовку; глобальные смены очищают локальную очередь. При выходе с первой карты ожидающие локальные запросы удаляются. Один callback завершает один реальный проход; следующий одноразовый сигнал подключается отложенно. До завершения очереди сохраняется прежний прямой fallback.

## Проверки

- 60 / 0 профильных утверждений: `tools/terrain_revision_review.gd`. Сохранность полного save, 1 200 правил земли, восьми настоящих движений у мостов и действий мотыга → семена → лейка. Повторные чтения не растят кеш, ошибочные данные и переполнение не теряют работу.
- 9 Python-сценариев `tools/test_terrain_revision.py` портят только временные копии. Проверяются потерянный запрос, пересозданная текстура, лишний target, весь clear вместо локального, посторонняя мутация save при поливе, рост работы на неизменном кадре, пиксель контрольного кадра, RGB и скрытая альфа вне области. `tools/terrain_revision_verify.py` входит в общий architecture gate.
- Нативная серия `tools/terrain_revision_collect.py`: 80 PNG / 212 полных наблюдений вокруг production draw, два окна 1152×648 / 1280×720, логические 1152×648, 120%. Свежие отдельные профили, точный архив 54 исходников до запуска, Git-база, SHA и все артефакты. Незавершённый JSON/ERROR не принимаются. Обычный Godot не закрывается; статическое сосуществование записано явно.
- Локальное оформление огорода: 69 120 изменённых пикселей / ноль снаружи, 288×240 вместо области 2400×1368. 2,105% — объявленная область записи, не время GPU и не ускорение FPS. Полный и локальный RGBA совпадают, идентичность target/текстуры сохраняется. Первый локальный кадр совпадает с первым кадром полного пути.
- Три раздельных участка включают водную кромку и мост. Повторная запись во время активного прохода не потеряна; полная смена на осень заменяет очередь. Вода сохраняет точную альфу. При изменении влажности перестраиваются только пять соседствующих мешей из 30, весь RGBA-кеш фона неизменен. Влажность нативной витрины задана профилем; реальные инструменты покрыты логическим профилем, физическое устройство ввода не заявляется.
- Прямые участки, дорожный поворот/Т-стык/тупик, оба моста, четыре настоящих календарных сезона и дом/возврат. Локальная запись и последующая полная перерисовка дают одинаковые кадры. За 120 неизменных callbacks ни фон, ни ресурсные ID, ни счётчики не меняются.

Полный игровой/architecture gate, Wiki check и браузер фиксируются в `completion.json` после реального прохождения. Откат `local_terrain_updates=false` сохраняет прежний полный метод, save-миграции нет. Новые bitmap-ресурсы не требуются.

## Ограничения приёмки

Рисунок напрямую и тот же рисунок через offscreen-кеш уже имеют различие семплирования: максимальная канальная дельта в этой серии 203/195. Оно не закрывается этой задачей; прямой путь не переписан. Сравнение первого локального/полного кадра точное, как и сравнение конечных двух способов обновления. Исторические VGROUND-008-сцены не используются как точный контроль: их начальные `containers/rng/world_loot_seed` отличаются; различия не замаскированы под успешную эквивалентность. Проверяемое сравнение идёт внутри текущей серии при одном полном состоянии.

Clear/scissor ограничивает область записи; CPU по-прежнему может пересобирать сохранённые команды целого terrain CanvasItem. Заявления об ускорении, GPU timer, RSS/VRAM или живом FPS не делаются. VPERF и итог всей карты VMAP-003 остаются открытыми; другие карты и механики не расширены.
