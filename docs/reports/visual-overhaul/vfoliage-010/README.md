# VFOLIAGE-010 — видимость и бюджет травы

[PR #7](https://github.com/sergey-leonidovich-shevchenko/babushkina-ferma/pull/7) открыт. Локальная проверка существующей травы выполнена; карточка остаётся `in_progress` до ревью текущего PR и решения Team Lead. Production scripts, игровые изображения и размещения не менялись. VRELEASE-003 и VMAP-003 ещё не приняты.

В двух настоящих окнах 1152×648 и 1280×720 снято 512 кадров. Все 36 пар обычного/отключённого отсечения имеют одинаковые RGBA ниже служебной полосы и одинаковые camera/state/save/uniforms. Записаны реальный системный фокус, устойчивая геометрия, два завершённых present и уникальный 16 битный маркер каждого кадра. Рисование не меняет сохранение. Профильный suite прошёл 131 условие.

Четыре ролика каждого окна — управляемые панорамы через края растений. Ещё два — настоящий герой со скоростью 210: переход через x1920 и путь вдоль кроны ягодного куста. Коллизии не отключались. Просмотр 24 кадра/с замедлен в 2.5 раза; контролируемые callbacks не являются аппаратным вводом или FPS. Прежние проверки четырёх подходов/бега/упора/телепортации/паузы остаются в полном Game; их исторические серии не переименованы в новую приёмку.

В контрольных QA-парах остаётся дочерний `WorldBackground` с землёй, берегом и мостом. Режим выводит родительский draw травы без героя и прочих актёров поверх этого общего фона; он не является прозрачной альфа-маской растений. Это не мешает точному сравнению отсечения при одинаковом фоне.

## Фактическая стоимость

| Показатель | Результат |
| --- | --- |
| Постоянные ресурсы | один owner, один target, две группы, восемь экземпляров |
| Обычный target обоих окон |768×384, две canvas draw calls,192 треугольника |
| Номинальный RGBA8 payload |1 179 648 байт (1.125MiB), без заявления об аппаратной VRAM |
| Ракурс cost, 1152×648: normal → low → returned |127 →124 →127 root canvas draw calls |
| Ракурс cost, 1280×720: normal → low → returned |126 →123 →126 root canvas draw calls |
| Low/offscreen |active0, recovery0, update disabled, прежний target ID |
| Максимальное наложение в диагностическом target |1 фрагмент на пиксель |

Числа 127 для окна 1152 и 126 для окна 1280 относятся к конкретному неподвижному ракурсу cost, а не ко всей карте во всех условиях. Счётчики target в low/offscreen сохраняют последние 2/192: это старый render-info, не новая GPU-работа. Отключение подтверждается update mode0 и отсутствием активных рядов. Глобальные texture/static memory записаны в каждом кадре, включая QA-кеши; они не выдаются за расход только травы.

Проверены 12 предельных target в каждом окне: scale1/2/4 и четыре угла коробки±5.71 поx,±4.36 поy. Калибровка 0/1/2 точна. Настоящие MultiMesh AABB покрывают полный ход вершин; PAD12 и mesh margin9 достаточны. Сумма фрагментов ниже заранее фиксированного лимита, максимум наложений 1:

| Scale | Площадь target | Сумма фрагментов, минимум…максимум | Доля площади |
| --- | --- | --- | --- |
|1 |73 728 |39 168…43 776 |53.125…59.375% |
|2 |294 912 |155 520…176 256 |52.734…59.766% |
|4 |1 179 648 |624 384…702 720 |52.930…59.570% |

Это покрытие геометрией подсистемы, включая прозрачные texel. Диагностический fragment заменён только у частных QA-target; игра его не использует. Whole-scene аппаратный overdraw, GPU-время и FPS этим способом не принимаются.

`tools/foliage_visibility_collect.py --output <новый каталог>` снимает два окна последовательно в отдельных новых профилях. Native-01 завершилась с первого запуска; предварительная калибровка отдельно помечена diagnostic-only. Ошибки начальной разработки CPU-стенда и прерванный запуск контролей сохраняются в `diagnostics`; они не являются зелёной приёмкой.

Для побайтного повтора **съёмки** нужен отдельный checkout закреплённого base `2fa58d3` с наложенной капсулой кандидата `sources.tar.gz` и теми же ресурсами/движком. Обычная повторная **проверка архива** работает и в будущей версии игры: анализатор сверяет исторические Git blobs и капсулу, а не текущий VERSION/production. План и капсула связаны с опубликованным коммитом `263b46f6` и прежними SHA256; все3743 сохранённых исходника проверяются без переподписывания данных.

Флаг `--check-current-candidate` отдельно требует точного совпадения текущего кандидата с историческими исходниками и состава production-файлов. После смены версии или игровой логики такой guard должен отказать; это не делает старый архив невалидным и не принимает новый код по старому видео. Для новой съёмки нужен новый заранее зафиксированный план.

`tools/foliage_visibility_pack.py <каталог>` проверяет побайтный decode каждого из 432 видеокадров перед очисткой промежуточных PNG успешной серии. Первичные lossless/exact WebP и неизменный `capture.json` остаются; ключевые 0/17/35, все 36 пар, cost и coverage PNG сохранены полностью. `storage.json` связывает исходный PNG SHA, decoded RGBA SHA и номер кадра. MP4 — производные для просмотра, не пиксельные эталоны. Неудачные серии упаковщик отвергает.

`tools/foliage_visibility_verify.py` независимо пересчитывает полноту матрицы, SHA, RGBA, коды маркера, реальные конечные координаты и additive coverage. `tools/test_foliage_visibility.py` проверяет повреждённые временные копии; повторное подписание метаданных не скрывает плохой пиксель или bounds. Оба включены в architecture. Команды и сырые результаты общих проверок сохраняются в `checks` перед PR. Локальный успех не означает одобрение head или зелёный GitHub CI.
