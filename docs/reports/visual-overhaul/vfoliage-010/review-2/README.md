# VFOLIAGE-010: Git inventory после повторного ревью

[Замечание P2](https://github.com/sergey-leonidovich-shevchenko/babushkina-ferma/pull/7#discussion_r4370635795) относится к head `d3bf8f792cbf264c6a169755dfd1e66d5b3b68ea`. Прежние P1/P2/P3 ревьюер признал исправленными, но не одобрил merge: строгая проверка в Git-копии видела только индекс и пропускала новый untracked-исходник.

## Исправление

В Git-ветке `verify_current_candidate` теперь используется `git ls-files -z --cached --others --exclude-standard`: учитываются индекс и новые неигнорируемые файлы в `scripts`, `assets/game`, `main.tscn`. Набор сравнивается с объявленной inventory до проверки SHA. Git ignore сохраняет область исходников, принятую при сборе; отслеживаемые файлы остаются в наборе и при наличии ignore-правила.

Добавлена регрессия именно с настоящей `.git` и индексом: восстановленный кандидат принимается с 3743 исходниками; затем создаётся `scripts/future_effect.gd`, проверяется его отсутствие в индексе и присутствие в untracked, после чего guard должен отказать. [Красный результат](red-regression.txt) получен на прежнем алгоритме: `ValueError not raised`. [Зелёный результат](green-regression.txt) — после исправления. Прежняя fixture без `.git` и все 32 контроля сохранены. С отдельным контролем hook-окружения полный набор содержит 34 сценария.

## Изоляция Git hook

По уточнению Team Lead собственные fixture очищают `GIT_*` в изолированном Python-окружении, включая создание class-level шаблона. Такой же подход уже используется в `test_task_batch`; чужой `test_shore_kit` не меняется.

Дополнительный контроль создаёт отдельный Git-родитель с config/index, затем запускает дочерний сценарий с унаследованными `GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, указывающими на родителя. Дочерний fixture проверяет очистку до любых `git init/add`. SHA конфигурации/индекса родителя должны сохраниться. [Результат](environment-regression.txt) и [отдельный аудит настоящего родительского repo](parent-repository-preserved.json) фиксируют также неизменность конфигурации/индекса рабочего проекта вокруг этого опыта; их содержимое не публикуется.

## Сохранность истории

Исторические функции provenance не менялись даже по AST; остальные модули reader побайтно равны предыдущему head. Вся предыдущая папка `review-1` и 223 первичных файла сохранены, новые планы/кадры/капсула не создавались и старые не переподписаны. [Аудит](preservation.json) связывает эти проверки с прежним head и manifest.

Metadata текущей правки — 0.0.337. Обычный исторический reader по-прежнему должен возвращать 512/36/24, а строгий guard не принимает изменённый текущий кандидат по старой съёмке. Новое исправление остаётся в PR #7 и `in_progress` до повторного ревью нового head, CI и решения Team Lead. Task-Complete и merge не выполняются.
