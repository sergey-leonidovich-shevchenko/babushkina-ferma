# VPERF-005 · Текстурная память первой деревни

При открытии деревни больше не нужны мастерские подвала. Их восемь атласов подгружаются при первом запросе спрайта соответствующего станка. Последующие кадры используют уже загруженный ресурс. После посещения всех мастерских эти атласы могут оставаться в памяти. Изменение уменьшает стартовую загрузку и не устанавливает верхний предел памяти всего мира.

## Сопоставление источников

| Источник | Конфигурация | Объём |
| --- | --- | ---: |
| [Ранняя диагностика](../../../epics/visual-overhaul-2026-10/evidence/native-1152.json) | Radeon Pro 5300M, окно 3584×2240, целевой буфер 1152×648 | 753 884 042 байта, 718,96 MiB по счётчику Godot |
| [VPERF-001](../vperf-001/README.md) | Radeon Pro 5300M, физическое окно 1152×648, три повтора и цикл 600 с | 683 335 708 байт максимума в каждом прогоне, 651,68 MiB по счётчику Godot |
| Статический граф принятой базы `c88db730` | 301 PNG по буквальным ссылкам от `main.tscn`, расчёт RGBA8 | 440 811 004 байта |
| Статический граф реализации | 293 PNG при том же способе подсчёта | 390 490 492 байта |
| Восемь отложенных атласов | 1254×1254 каждый, 8-битный RGBA, lossless, без mipmaps и ограничения размера | 50 320 512 байт по формату, 16 382 905 байт файлов PNG |

Сумма RGBA8 описывает объём пикселей по формату. PNG занимает место на диске, а счётчик Godot показывает учтённые движком текстуры конкретного запуска, включая ресурсы вне статического графа. Сравнение до и после выполняется на одном X11-раннере с Mesa llvmpipe. На нём можно проверить загрузку ресурсов и показания движка. Физическая VRAM, кадровый бюджет на Radeon и время исполнения GPU требуют собственных замеров.

В реализации сохранены существующие PNG, настройки импорта, 96 регионов и три ракурса. Старое направление вверх по-прежнему показывает передний рисунок. Иконки предметов и станок в деревне используют прежний путь отрисовки. Кеш ограничен сочетаниями восьми видов, четырёх состояний и трёх направлений.

## Воспроизводимость

На одном удалённом раннере по очереди снимаются три повтора по 30 секунд и один цикл по 600 секунд для каждого состояния. Каждому запуску выделены свой процесс и свежий профиль. Окно, буфер и снимок имеют размер 1152×648. Камера находится в точке `(120.25, 430.25)` при масштабе 120%. Симуляция продолжает работу во время замера. Из каждой ревизии берётся её штатный измеритель VPERF-001. [Рабочий процесс VPERF-005](../../../../.github/workflows/vperf-005.yml).

Архив прогона содержит исходные интервалы idle loop и `frame_post_draw`, draw calls, счётчики текстур и статической памяти, отдельное RSS процесса, настройки и два оконных кадра. Нулевые показания текстур обрабатываются как недоступные или неполные. Время GPU в отчёте отсутствует. Отдельный наблюдатель до замера снимает одну и ту же деревню и строящийся пресс, сверяет импортированные размеры, формат и пиксели атласов и проверяет сохранение и восстановление стройки.

Сборщик сверяет полный набор экспортированных исходников с Git. Квитанция каждого процесса записывает режим, повтор, SHA, дерево и путь проверенного экспорта вместе с хешами файлов этого запуска. Офлайн-проверка на копиях VPERF-001 подтвердила, что перестановка каталогов baseline и candidate отклоняется даже после пересчёта внешних хешей. Все показатели исходной пары совпали с прежним пересчётом.

Визуальный контроль ждёт восемь кадров в устойчивом окне X11, минимум 500 мс и не более 8 секунд. Перед записью PNG повторно проверяются фокус и размер 1152×648. При отказе сборщик сохраняет `window-error.json` с фактическими размерами, состоянием фокуса и причиной.

Команда инвентаризации на Python 3.11 работает без запуска Godot.

```sh
python tools/run.py qa.performance.texture_budget.inventory --output /tmp/vperf-005-inventory.json
```

Эта команда повторно проверяет распакованный архив с сырыми данными.

```sh
python tools/run.py qa.performance.texture_budget.pair verify --output /path/to/evidence --expected-head <full-sha>
```

Статические размеры и состав графа перепроверены. Нативные результаты будут записаны после прогона опубликованной ревизии.
