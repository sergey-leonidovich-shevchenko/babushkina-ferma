# VFOLIAGE-002 · Локальные UV и изоляция ячейки

Выполнена одна следующая карточка после VFOLIAGE-001. На старте checkout был чистым, main `e3b3db23` опережала origin без расхождения, активных задач не было. Полное замыкание живого пилота содержало 55 карточек, из них 37 завершены. VFOLIAGE-002 была ready, единственная прямая зависимость и все её предшественники — done.

## Результат

Новый `FoliageUV` подготавливает локальную сетку, параметры области и отдельный материал. Shader переводит локальные UV в пиксели исходника и ограничивает выборку центрами крайних texel: от 0,5 до размера−0,5. Поэтому linear-фильтр не читает соседнюю ячейку даже при проверочном выходе UV за область. Mipmap-фильтр и повтор текстуры не включаются; произвольная минификация с mipmaps требует отдельной подготовки atlas gutters, не обещается этой карточкой.

Отражается только X. У зеркальной сетки горизонтальная координата опоры меняется на `width-root.x`, Y сохраняется. В сетку включены отдельные ряды неподвижного основания и реального корня из VFOLIAGE-001. Shader вычисляет вес по локальному Y, независимо от цвета вершины; камни, пни, ограда, фонарь, мостик и плавающий декор не деформируются. Вертикальный flip API не предоставляет.

`bend` по умолчанию нулевой. Статические воздействия ±8 по X и ±5 по Y используются только на QA-стенде; shader ограничивает обе оси диапазоном±8, а mesh AABB заранее расширен. Встроенного TIME, игрового update, нового контакта или ветра здесь нет. Маска L8 передаётся отдельным числовым sampler без source_color; цвет исходника имеет свой sampler. Каждый материал владеет своими параметрами, глобального изменяемого материала или shader-global нет.

Обычный renderer не переключён на новый способ: это готовый контракт для следующего подключения. Игровые PNG, размещения, физические клетки, сохранения, существующие механики и календарь не мигрировали. Два новых runtime-файла перечислены в [changes.json](changes.json); исходники и QA-overlay закреплены в [source.json](native/source.json).

## GPU-проверка

Проверены все 13 профилей, оба отражения и три статических воздействия. Для каждого случая созданы три отдельных SubViewport192×192 при измеренной проекции 120%:

1. Исходник внутри большого атласа, все соседние ячейки окрашены яркими контрольными цветами.
2. Тот же исходник отдельно, на точно такой же сетке: строгая проверка выборки, максимум 1/255 по полному RGBA.
3. Независимый эталон отражения: обычная немирроренная сетка с отрицательным X-масштабом узла и компенсированным направлением воздействия. Допуск 2/255 учитывает растеризацию другой геометрии; этот допуск не применяется к основной проверке выборки.

Четыре намеренно неверных shader-контроля убирают clamp при UV−0,1…1,1. Они обязаны захватить соседние цвета: max≥64/255 и не менее 500 изменённых пикселей. Фактический максимум 244/255, тысячи пикселей. Проверяются полные targets, края из сравнения не исключаются. Дополнительно весь нижний участок закреплённого основания сравнивается побайтно между воздействиями; для восьми жёстких/плавающих видов точен весь target.

Итого: **156 корректных GPU-троек +4 ошибочных**, **480 target PNG**, **960 callback реальных MeshInstance2D**, **320 игровых и 320 витринных callback** в двух физических окнах 1152×648 и 1280×720. Все 80 случаев каждого окна имеют два фактических draw каждого mesh, измеренные uniform, shader SHA, матрицу отражения, размеры/проекцию и активность 1→0 у каждого из трёх владельцев. Полный игровой snapshot закреплён исходным JSON-текстом и SHA; состояния до/после каждого draw равны.

Фокус честно записан, отсутствующий фокус не подменяется. Это статический GPU-протокол, не физическая проверка клавиатуры, FPS/память или приёмка живого пилота/VMAP-003. [Условия](native-admission.json) и [сводка](summary.json).

Первый исследовательский запуск отклонён из-за canvas_transform до присоединения viewport. Во втором сравнении точность выборки была смешана с отражением другой геометрией; принятая свежая третья серия разделяет эти проверки и содержит отдельные эталоны. Отклонённые файлы не переподписывались. В verifier значения float32 проекции сравниваются с явным допуском 1e−6; геометрия окна и target — точные.

## Проверки и воспроизведение

Профиль **413/0**, включая отдельный валидатор русских комментариев; игровой suite добавляет 412 условий. Проверены все области, центры крайних texel, оба flip, реальные корни, нижние ряды, culling envelope, независимые материалы, неверные ID/размеры/координаты, одинаковый ввод/seed, stop/столкновение/QA-перенос/пауза/offscreen/reduced-motion и отсутствие новых игровых узлов/metadata/полей сохранения.

**21 Python-сценарий** проверяет настоящую серию и портит только копии: неверные uniform/шейдер/flip, изменение Y или нижней полосы, невидимое окно, ложную приёмку FPS/hardware, потерю callback, ownership, snapshot, пиксель, исчезнувший отрицательный контроль и подменённый архивный код. Исторические исходники читаются из неизменного Git-base. Фактические общие результаты и Wiki — в completion.json после завершения.

Команды: `tools/foliage_uv_review.gd`, `python3 tools/foliage_uv_verify.py`, `python3 tools/test_foliage_uv.py`. Повторный сбор требует нового каталога и профиля Codex-VFOLIAGE-002. Сохранения пользователя не читаются. Откат — отдельный revert двух новых runtime-ресурсов; штатный renderer этой карточкой не заменён.
