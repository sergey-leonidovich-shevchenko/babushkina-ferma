# VLIGHT-003 — день и сумерки

Старт 20 ноября 2026: main `c1f2eda0d1d36e1491dab32fef090bb5a3d22e12`,
версия 0.0.471; ветка `codex/vlight-003-visual-task`. Карточка остаётся
`in_progress` до независимого ревью, решения Team Lead и merge.

## Зависимости и границы

Прямая зависимость VLIGHT-001 принята. Полное замыкание:
VBASE-003 → VBASE-004 → VART-001 → VART-007, VBASE-001 → VRENDER-001,
затем VLIGHT-001: семь done-карточек, внешних needs нет. Отдельно проверены
принятые VLIGHT-002, VART-003, VCAMERA-006, VRENDER-008, VRELEASE-005.
Исторические evidence содержат Markdown-ссылки, пояснения и прежние пути tools;
наличие строки не подменяет проверку её действительного источника.

Меняется только общее освещение первой `overworld`. Мягкая графика A,
«Тёплая долина», масштаб 120%, post-motion, геометрия, ресурсы фонаря и принятое
решение VLIGHT-002 сохраняются. Другие карты, интерьеры, механики, календарные
события, сохранения, UI-настройки и погода не переделываются. VMAP-003 не принят.

До изменения runtime сохранён локальный снимок: остальные 1036 visual-карточек,
метаданные backlog, 132 файла доказательств VLIGHT-001/002 и SHA planning state/sources.
Эти данные не являются новыми доказательствами рендера и должны остаться неизменными.

## Решение

`game_minutes` уже дробные: одна секунда симуляции — одна игровая минута.
Новый таймер не нужен. Чистая функция календарных минут выдаёт один RGBA:
плавный smoothstep между 05:00–07:00 и 18:00–20:00; небольшой тёплый пик внутри
каждого перехода. День прозрачен, ночь совпадает с существующим холодным tint.
Ночная непрозрачность ограничена прежними 0.62; коэффициенты конечны и цикличны.
Тёплая составляющая опирается на свет дерева `#e4cb94` принятой палитры A.
Две составляющие сводятся в один обычный alpha-mix прямоугольник, без новых
узлов, материалов, текстур, viewport, screen-copy и растущих кешей в игре.

AtmosphereRenderer остаётся перед draw_screen. HUD не получает общий modulate.
Затмение и остальные локации идут по прежнему пути. Reference mode по-прежнему
выключает эффекты; временный строго булевый флаг отдельного игрового canvas
возвращает прежний tint для сравнения и отката без записи save/config.
Интенсивность существующих фонарей, is_night и eclipse_active не меняются.

## Проверки до приёмки

1. Модель: точные день/ночь, цикличность, NaN/Inf, ограничение alpha, непрерывность
   значения и первой производной на четырёх переходах и полуночи; дробные минуты,
   независимые владельцы флага, неверный тип, reference mode и неизменность save.
2. Настоящий Godot 4.7.1 Compatibility в удалённом Linux CI/X11/Mesa: закреплённая
   старая main и текущий Git tree, одинаковые камера/seed/полные save, два размера
   окна, рассвет/день/сумерки/ночь, существующая комната как отрицательная область.
   Legacy-флаг в текущем runtime должен совпасть со старым runtime.
3. Нормальный production root с настоящим HUD, отдельный прозрачный HUD для
   анализа непрозрачных пикселей, независимые viewport с разными минутами.
   Полный RGBA HUD нового профиля и legacy сравнивается с HUD принятой main
   при тех же часах: два одинаково ошибочно перекрашенных кадра не подтверждают
   друг друга. Совпадение root/HUD-only само по себе недостаточно.
   Опасности и герой должны оставаться видимыми; области и пороги объявляются
   до принятия результата. Reference/effect-off, затмение и соседняя карта
   проверяются отдельно. Состояние и геометрия сравниваются до/после draw.
4. Нативный отрицательный контроль: неправильное затемнение HUD должно быть
   отвергнуто тем же reader даже при корректно обновлённых SHA. Подмена PNG,
   неполная матрица, чужие Git/producer, изменённый save, общий viewport/time,
   усечённые/NaN временные samples также должны отклоняться.
5. Три чередующихся повтора on/legacy/effect-off без PNG readback во временной
   серии. Сохраняются все CPU draw submission и wall-frame samples; X11 software
   rendering не объявляется измерением GPU, Mac/Retina FPS или общей оптимизацией.
6. Полный штатный hook, новые профильные тесты и Wiki check. Браузер 4174:
   действительная карточка/поиск/статья/нативные изображения/вложения, 390 px.
   Автор читает итоговый diff; PR/CI и независимое exact-head review обязательны.

Нативный игровой запуск выполняется в CI/удалённом стенде. Локально допустимы
изолированные headless compile/тесты. Перед каждым движком — фактическая проверка
занятости; тяжёлые фазы исполняются последовательно. Чужие процессы не управляются.

В QA `legacy` выключает именно новую палитру, сохраняя прежнее затемнение;
`reference` отключает существующий диагностический набор эффектов первой карты.
Последний не выдаётся за изолированную стоимость одного tint. Прежний source-probe
VLIGHT-001 предназначен для его принятого commit dc4429f8; его регрессионные
тесты теперь явно читают эту историю. Сам probe, его принятый пакет и reader
не переписываются; новый live renderer старым прибором должен быть отвергнут.

Исторические corruption-сценарии VLIGHT-002 проверяют свой Git/QA-пакет без
утверждения, что он совпадает с новым live renderer. Current-guard отдельно
проходит в настоящем временном checkout принятой базы с замороженными QA-входами
и отвергает контролируемое изменение runtime; index/config родительского проекта
сравниваются до/после. Сам accepted reader и его защита не ослабляются.

Перед native уточнены границы прибора: seed восстанавливается после set_script
и проверяется по настоящему save; герой и угроза снимаются с независимыми
контролями без одного объекта. Логические ROI преобразуются фактическим stretch
viewport в framebuffer. Reader сверяет камеру/масштаб/области с допуском1px
для float-округления; сдвинутая или оставленная в логических пикселях область
отвергается. Все эти изменения относятся к QA, не к игровой механике.

## Доказательства и откат

Нативный пакет сохраняет Git SHA/tree, байты QA/оверлеев, инвентарь игровых
ресурсов, реальные argv/exit/log/profile/renderer, полные JSON и исходные PNG.
Неудачные прогоны остаются диагностикой. Повтор получает новую внешнюю папку;
принятый архив не перезаписывается. Последующие SemVer/report-коммиты объявляются
отдельно и не маскируют изменение runtime после съёмки.

Откат — отдельный commit удаления подключения палитры либо временный per-canvas
legacy-флаг. Никакой миграции сохранений и правки frozen VLIGHT-001/002 нет.

Источники API: [CanvasItem shaders, обычный alpha blend_mix](https://docs.godotengine.org/en/stable/tutorials/shaders/shader_reference/canvas_item_shader.html),
[CanvasItem draw_rect](https://docs.godotengine.org/en/stable/classes/class_canvasitem.html),
[CanvasLayer и принадлежность viewport](https://docs.godotengine.org/en/stable/classes/class_canvaslayer.html).
Это основания реализации, не доказательство качества полученного кадра.
