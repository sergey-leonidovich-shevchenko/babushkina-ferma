# VFOLIAGE-009: неизменяемый протокол нативной проверки

До первого native запуска фиксируются исходники и порядок: два новых изолированных процесса1152×648 и1280×720; существующая main, 120% zoom, прежняя первая карта и восемь растений. Для шкафа/сундука используется прежний дом и его существующий API, без нового интерьерного дизайна. Только ручные реальные physics/process callback с delta1/60, автоматические игровые такты отключены. Это не FPS, реальная клавиатура или аппаратный допуск.

13 режимов по порядку plan.json, каждый в новой сцене:12 разрешённых начальных шагов, before; открыть существующее окно/API, один остановленный шаг, entered; ещё36 остановленных шагов, held; закрыть окно, один разрешённый шаг, resumed1; ещё11 шагов, resumed12. Домашний возврат в QA задаётся явно, не выдаётся за штатный маршрут VRELEASE-003. Focus/app notifications синтетически подаются существующему обработчику; фоновое разрешение проверяется отдельно CPU-тестом. Редактор намеренно использует прежний статичный fallback и владеет своей камерой; low/reduced/reference не получают новую политику этой карточкой.

Всего65 состояний на процесс/130 на два окна. Каждый state сохраняет полный визуальный и игровой snapshot через проверяемый SHA-индекс, реальные material uniforms, clock, камеру, память восстановления и счётчики. Все36 промежуточных paused отсчётов содержат clock и ссылки на полные снимки. Entered/held обязаны совпасть по визуальному state и полному сохранению; настоящие GPU target RGBA — побайтно. Первый resume продвигает только1/60, двенадцатый —12/60, без долга; новых владельцев/target нет. Шкаф/сундук и F12 дают прежний fallback/неактивность согласно runtime, не анимированный остаток чужой карты.

Окно читается только после двух настоящих frame_post_draw с дедлайном5с. Пять фаз имеют разные чистые RGB-маркеры той же CanvasItem после production draw; draw tag и pixel marker обязательны. В каждом capture сохраняются actual root/image/target sizes, focus/visibility и before/after saved-state. GPU target вправе не перерисовываться на паузе: одинаковый target не подменяет свежесть самого окна. Оба реальных размера должны различаться; герой/мир не меняются ради изображения. Сравнения выполняются внутри одной камеры/состояния; редакторская камера и домашний переход явно отмечены.

Свежая папка и профиль обязательны, повторный output запрещён до записи. Все failed/partial материалы сохраняются, никакой выборки удачных дублей; при ошибке остановить принятие и записать причину. При необходимом исправлении QA старый план/источники/результат не переписывать, оформить erratum. Production сейчас не меняется: задача проверяет существующую политику; лишний runtime patch без воспроизведения не нужен.

После съёмки независимый Python verifier проверяет матрицу/порядок, SHA снимков и файлов, точные RGBA target, реальные draw/present, timestamps/clock deltas, лимиты и совпадение источников. Отрицательные контроли портят только копии настоящих данных. Статус остаётся in_progress до exact-head CI/review и решения Team Lead; VRELEASE-003/GPU/VMAP-003 этим не закрываются.
