## Проверяемая политика

Сценарий вызывает настоящие API рюкзака, журнала, героя, карты, паузы, настроек, подтверждения выхода, focus-out/app-suspended, focus-out с рюкзаком, редактора, шкафа и сундука. Три delta: 1/30, 1/60 и 1/120. Профиль `tools/foliage_pause_review.gd` ранее прошёл 2966 утверждений; тот же suite входит в полный игровой набор. На каждом из 36 шагов паузы сравниваются полные visual state и save, camera, physical frame, часы, uniforms, contacts/recovery и счётчики. Первый разрешённый шаг добавляет только текущий delta.

Отдельно проверены opt-out автопаузы и возврат фокуса с вручную открытым рюкзаком. Уведомления подаются синтетически настоящему обработчику; это не физическое переключение приложений. Реальный фокус самого окна при нативной съёмке проверяется независимо и обязателен в каждом кадре. Домашние окна открываются в прежнем cottage_interior; возврат в overworld явно задаёт QA, без приёмки штатного маршрута VRELEASE-003. Редактор/дом используют прежний fallback/zoom 1.0, overworld — 1.2.

Остаются один владелец, две группы, один target и не более 64 записей восстановления. Четыре подхода, бег, остановка, стена, телепорт, offscreen и low сохраняют принятые контракты VFOLIAGE-004…006. Эта карточка добавляет полную матрицу причин паузы.

## Подготовка окна и критерии

После третьего отказа только в QA добавлено ожидание завершения перехода macOS до начала матрицы: максимум 7 с, не раньше 1500 мс и затем не менее 500 мс устойчивого оконного режима и совпадения реальных размеров root/readback. В последней серии записаны все 117 наблюдений startup_geometry каждого процесса. Это подготовка окна до тестовых фаз. Во время фаз дополнительные физические шаги для подбора изображения не выполняются; отсутствие маркера после двух present по-прежнему даёт отказ.

В каждой фазе сохраняются фактические размеры, фокус/видимость/оконный режим, draw tag, material uniforms, полные state/save через проверяемый SHA-индекс, PNG окна и настоящего SubViewport. Entered/held имеют одинаковые target RGBA, визуальный state и save. Рисование/readback не меняют игру. После resumed1 часы равны paused+1/60, после resumed12 — paused+12/60; target снова меняется. Неактивные editor/household сохраняют штатный fallback и очищают recovery.

Независимый Python verifier сверяет планы/архивы/файлы, runtime с Git-базой, полную матрицу и порядок, 936 промежуточных отсчётов, реальные размеры и native pixels. 18 контролей портят только временные копии/снимки в памяти: пропущенная фаза/отсчёт, snapshot SHA, повторно подписанный неверный clock, render mutation, отсутствие draw/present, fullscreen, неверный пиксель target, artifact SHA, невозможные timestamps, отсутствие устойчивой геометрии и ложные FPS/аппаратные флаги. Исторические отказы всё ещё отклоняются. Синтетические focus=true parser fixtures первой серии проверяют отдельные ограничения и никогда не выдаются за нативный допуск; положительный полный verify использует новую настоящую серию.

```sh
python3 tools/foliage_pause_verify.py
python3 tools/test_foliage_pause.py
# Исторический отказ по-прежнему даёт ненулевой exit:
python3 tools/foliage_pause_verify.py --output docs/reports/visual-overhaul/vfoliage-009/native-focused --plan docs/reports/visual-overhaul/vfoliage-009/plan-focused.json
```

## Проверки и пределы

[Предыдущие общие проверки](checks.json) относятся к опубликованной подготовке до возобновления; raw/SHA сохранены. Новая полная серия прошла независимый verify и 18 контролей. Новые [проверки после возобновления](checks-windowed.json) прошли: architecture; полный Game 53 371/0 и normal/F10 redraw по 90/0; Wiki build и 135/0; independent native verify и 18/0 контролей. Браузер подтвердил статью, поиск, статус карточки и шесть точных JSON-вложений. Статья и карточка остаются в работе, ожидают CI и ревью.

Это контролируемые вызовы actual-main и настоящие GPU readback, без приёмки физической клавиатуры, FPS или аппаратного бюджета. VFOLIAGE-010, VRELEASE-003 и VMAP-003 не закрываются этой карточкой. Слияние требует отдельного одобрения точного текущего head и решения Team Lead; новую задачу до этого не выбираем.
