## Проверенная политика

`tests/helpers/foliage_pause_scenario.gd` вызывает реальные API рюкзака, журнала, героя, карты, меню паузы, настроек, подтверждения выхода, уведомлений фокуса/приостановки, редактора, шкафа и сундука. Три delta —1/30,1/60,1/120;36 остановленных шагов на каждый случай. Все 2966 утверждений профильного `tools/foliage_pause_review.gd` прошли: часы, physical frame, камера, uniforms, contacts/recovery, счётчики и полное сохранение неизменны; первый разрешённый шаг продвигает только текущий delta.

Отдельно проверены разрешённая работа в фоне и возвращение фокуса при вручную открытом рюкзаке. Уведомления подаются синтетически существующему обработчику; это не испытание физического переключения приложений. Существующие домашние окна проверяются в прежнем `cottage_interior`; возврат в overworld явно задаёт QA. Редактор и домашние окна используют штатный zoom1.0/статичный fallback, первая карта —1.2. Никакой новой графики интерьеров или механик нет.

Фильтр затухания продвигается только с игровыми часами. Рисование/readback не должны менять state или save. Остаются один владелец, две группы, один target и не более 64 записей восстановления. Четыре подхода, бег, остановка, стена, телепорт, offscreen и low остаются покрыты принятыми VFOLIAGE-004…006; эта карточка добавляет полную матрицу причин паузы.

## Нативные попытки — обе отклонены

Первый неизменяемый [протокол](PLAN.md) и [план с SHA403 исходников](plan.json) закреплены до съёмки. `inputs.zip` содержит именно эти байты. В `native/` сохранены два отдельных процесса 1152×648/1280×720,13 режимов ×5 фаз,260 PNG и 936 промежуточных отсчётов паузы. Получены настоящие frame_post_draw, draw-tag и цветные пиксели фаз; target entered/held побайтно одинаков, после разрешённых шагов снова меняется. Однако **все 130 оконных кадров имеют focused=false**, поэтому серия не принята. `complete=true` здесь означает завершение сбора, а не допуск. Независимый verifier отклоняет её.

Перед второй попыткой записаны [erratum и прежние ограничения](PLAN-focused.md), [новый план](plan-focused.json), `inputs-focused.zip`. Единственное изменение QA — вывести собственное окно на передний план и ждать действительного фокуса до 3с. `native-focused/` остановлен до первого игрового кадра с `inventory: actual native focus unavailable`; `complete=false`. Данные первой попытки не перезаписаны и не выбраны только удачные дубли. macOS сообщает `CGSSessionScreenIsLocked=Yes`; исходный системный диагноз сохранён в `controls/native-focus-unavailable.json`.

Обе серии нужны для аудита отказа и не подтверждают готовность к слиянию. Для следующей попытки нужен разблокированный дисплей, заранее закреплённый следующий план и свежие output/profile. Параметры, данные и критерии не ослаблять.
