18 октября 2026. Ветка `codex/vpipeline-006-visual-task`, база `8706887e3647d4c0ef9b47bf18d4a3433cbd64c3`. Нативная приёмка 0.0.240 / Godot 4.7.1, Compatibility/OpenGL, AMD Radeon Pro 5300M. [Историческая пара](proof.json), [до](before/capture.json), [после](after/capture.json), [проверки](verification.json), [Wiki](../../../../wiki/articles/item-icon-sizes.md). Завершение ищется по `Task-Complete: VPIPELINE-006`.

## Решение

Размеры 64 и 160 уже были подготовлены для всех 386 предметов. Открытие шкафа использовало отложенный путь VPIPELINE-004 и предыдущей оптимизации: гипотеза о массовой загрузке оригиналов этим окном не подтвердилась. Заново создавать тот же пакет не потребовалось.

Контракт закреплён в `PreparedItemIconSystem`: размеры берутся из существующего канонического `catalog.gd`, а не из второго паспорта. До 64 включительно выбирается миниатюра; при уменьшении действуют подготовленные независимые уровни 64/32/16/8 VPIPELINE-004. При размере строго больше 64 выбирается отдельный 160px PNG. Например, 40→64, 64→64, 64,001→160, 104→160. Нулевые/отрицательные/нечисловые запросы не загружают оригиналы и не растят кеш. Размер фактической ячейки не меняется.

Пакет явно возвращает `prepared_role`, `prepared_size` и `texture_intent=color_srgb`, сохраняя provider, tint и приоритет выбранных замен. Если пользовательская замена не соответствует подготовленному индексу, остаётся прежний путь этой замены; stale-миниатюра не подменяет выбранный рисунок. Канонический API оригиналов для оружия, Wiki и сборщика сохранён.

Крупные превью получили самостоятельный `painted_ui`/linear с запрещённым повторением. Их CanvasTexture делит существующий исходник; шрифты, полотно, миниатюры и исходные PNG не переключаются глобально. Лимит LRU остаётся 16. Добавлены счётчики **запросов загрузки** (`preview_load_requests`), попаданий, вытеснений и копия списка удерживаемых ID. Счётчик запроса не выдаётся за дисковое чтение или декодирование: ResourceLoader может вернуть уже существующий ресурс.

Общий offline-fitter вынесен в `tools/item_ui_fitter.gd`, сборщик делегирует ему прежний алгоритм. В живой отрисовке нет resize/get_image/обрезки. Все 386 реальных PNG 160×160 побайтово совпали с повторным прямым экспортом полного канонического источника с полем 8. Это дополнительно к прежнему `sourceHash`, а не только проверка размеров. Маленький PNG не используется как источник большого. Алгоритм экспортёра общий; независимые проверки размера, альфы, областей и нативной загрузки дополняют его, не объявляя алгоритм доказанным самим собой.

## Нативная загрузка

Два отдельных свежих процесса, профили `Codex-VPIPELINE-006-before-final` и `…-after-final`; для baseline подставлены именно два исходных файла из указанного commit с гарантированным возвратом изменений. Один и тот же capture-скрипт связан SHA256. [Журналы](before.log) и [новый запуск](after.log) без ошибок движка.

Камера комнаты `[0,6]`, герой `[576,500]`, seed 20261015, время 720, framebuffer 1152×648, UI 1.0. Игра сначала рисует обычную комнату, затем первый раз открывает шкаф, рисует первый видимый кадр, стабильный кадр и повторное открытие. До окна не вызываются поставщики иконок для прогрева. Матрица проверяет загрузку окна после обычного старта игры; это не замер полного старта приложения или FPS.

| Момент | Крупные превью в ResourceLoader | Новые оригиналы PNG ради окна | Запросы загрузки превью после изменения |
|---|---|---|---|
| Комната | 0 | 0 | 0 |
| `open`, до draw | 0 | 0 | 0 |
| Первый видимый кадр | 1, `pirate_cutlass` | 0 | 1 |
| 20 повторных кадров | То же 1 | 0 | 1 |
| Повторное открытие | То же 1 | 0 | 1 |

В baseline те же количества ресурсов: массовой загрузки не было и до задачи. Во время старта игры уже присутствовали 151 ID с уже доступным исходником в ResourceLoader и 165 записей кеша специализированных поставщиков; это названная существующая загрузка, не ноль текстур во всём приложении. Из 221 лениво зарегистрированного PNG пути не загружено ни одного ради сеток и превью (`loaded_paths=0`). Сравниваются полные списки cached-ID до и после, а не только число удерживаемых Prepared-ссылок.

LRU проверен отдельно: после 16 разных превью повторный доступ не вызывает load; недавно выбранный остаётся после 17-го, второе вытесняется; слабые ссылки и на обёртку, и на исходник становятся пустыми. Возврат к вытесненному ID запрашивает ровно его, предел 16 сохраняется. Расчёт верхней границы пикселей больших превью — 16×160×160×4 = 1 638 400 байт (1,5625 МиБ), без накладных расходов GPU/драйвера. Это не измерение VRAM или FPS. Страницы миниатюр и их цена остаются из VPIPELINE-004.

## Картинка и сохранение

Полная комната совпала по всем RGBA-пикселям. В окне различаются 2016 пикселей выбранного рисунка внутри `[454,262,558,366]`: линейная выборка вместо наследованного nearest. За пределами этой области совпали сетки, шрифты, количества, кнопки, размеры и цвета. Первый, стабильный и повторно открытый кадры внутри каждого варианта полностью совпали.

Полные снимки сериализуемой модели до и после сохранены. Старое открытие шкафа штатно добавляет два события `dev_cabinet`: в `tutorial.events` и `estate.expansion.first_chapter.events`. Валидатор допускает именно эти две записи `true`; все остальные поля должны совпасть. В новой версии получились те же before/after снимки, что и в baseline. Запасы, время, здоровье, энергия и предметы не менялись. Сам временный склад не включается в обычное сохранение.

Исторические PNG и SHA256 проверяют эту пару; будущая принятая графика вправе измениться в своих задачах. Текущий пакет отдельно сверяется с актуальным реестром и каноническими исходниками при полном тестировании. VART-010 остаётся эталоном рисунка; новая партия VICON не перенесена, старые прототипы не объявлены перерисованными. WATER/VSHORE, VFOLIAGE, VLIGHT, VACTOR/VANIM/VBUILD и карты продолжают свои карточки. PACK использует тот же поставщик, не вводя ещё один набор иконок. FAIR/RELIC/CASE/ECHO и предложения IDEA не реализуются этой технической задачей; OPT-03 целиком не закрыт.

## Проверить и повторить

`python3 tools/item_sizes.py`: зеркала каталога, реальные 64/160 PNG, alpha-padding 3/8, source rect, provider/tint/sourceHash, lossless/no-mip/no-premultiply, настоящие нативные кадры, модель и холодные ссылки. Каждый обязательный файл доказательства должен присутствовать в Git index. Изменение контрольной суммы не скрывает неверный RGB вне выбранного превью.

`tools/test_item_sizes.py` — 9 сценариев на копиях: неверные размеры/проекция, overlap, повреждение/уменьшение PNG, срез/пустая альфа, импорт и fingerprint, скрытый прогрев/загрузка мастеров, повторный load, изменение сохранения и непрозрачного RGB вне превью. `ItemSizesSuite` входит в полный набор; профиль `tools/item_sizes_review.gd` дал 1204 утверждения, включая все 386 прямых экспортов. Негативные тесты не портят рабочие ресурсы.
