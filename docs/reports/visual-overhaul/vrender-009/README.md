# VRENDER-009 — изоляция нескольких viewport

Кандидат связывает каждый игровой мир с собственными `Viewport` и `WorldBackground`. Проекция, декоративное время и post-motion пакет принимаются только от этого владельца. В контекст входят три числовых ID; игровые узлы и сохраняемые данные туда не попадают.

Нативный стенд создаёт два настоящих `SubViewport` 1152×648 и проходит пять случаев: одинаковая камера, движение одного мира, F12/ручная пауза, вход в `village_market`, возврат в `overworld`. Сравнительные PNG лежат в `native/`; полные состояния, параметры запуска и владельцы — в `native/capture.json`.

`summary.json` сформирован командой `python3 tools/run.py qa.world.viewport_isolation_verify --write`. Для R11F сверяются capture, 15 PNG, параметры запуска и 27 файлов из коммита `f4d1a04d`, где сохранены точные байты съёмки версии 0.0.414. Манифест сверяется с индексом, а список изменений исходников — с базовым коммитом `976353fc`. Проверка охватывает 20 production draw, 20 полных save-пар и изоляцию двух настоящих `SubViewport` в обе стороны. FPS и приёмка VMAP-003 проверяются отдельно.

Для новой съёмки `--seal` сверяет рабочие исходники с захватом. После добавления манифеста в индекс `--check-current-candidate` проверяет совпадение текущих файлов с пакетом. После коммита `--bind-source-commit <SHA>` закрепляет точные Git blobs. Затем добавьте обновлённый манифест в индекс и обновите сводку через `--write`. Обычный архитектурный прогон сверяет исторические исходники с закреплённым коммитом и проходит после смены версии проекта.

Ленивая инициализация пустых разделов алхимии и магии остаётся в bootstrap. Старые сохранения без `expansion.fences` теперь нормализуются непосредственно при применении состояния, поэтому первый настоящий draw не меняет snapshot. Забракованные локальные серии R3–R9 не входят в отчёт.
