# VRENDER-009 — изоляция нескольких viewport

Кандидат связывает каждый игровой мир с собственными `Viewport` и `WorldBackground`. Проекция, декоративное время и post-motion пакет принимаются только от этого владельца. В контекст входят три числовых ID; игровые узлы и сохраняемые данные туда не попадают.

Нативный стенд создаёт два настоящих `SubViewport` 1152×648 и проходит пять случаев: одинаковая камера, движение одного мира, F12/ручная пауза, вход в `village_market`, возврат в `overworld`. Сравнительные PNG лежат в `native/`; полные состояния, параметры запуска и владельцы — в `native/capture.json`.

`summary.json` сформирован `python3 tools/run.py qa.world.viewport_isolation_verify --write`. Проверка связывает R11F с настоящим базовым commit `976353fc`, точным overlay исходников и Git-indexed `evidence-manifest.json`; отдельно сверяются байты capture, 15 PNG, профиль запуска и 27 runtime/test/quality-файлов. Валидируются 20 production draw, 20 полных save-пар, перенос мира между настоящими `SubViewport` и влияние в обе стороны. Это не FPS-допуск и не завершение VMAP-003.

Ленивая инициализация пустых разделов алхимии и магии остаётся в bootstrap. Старые сохранения без `expansion.fences` теперь нормализуются непосредственно при применении состояния, поэтому первый настоящий draw не меняет snapshot. Забракованные локальные серии R3–R9 не входят в отчёт.
