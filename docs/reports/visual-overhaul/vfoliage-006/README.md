# VFOLIAGE-006 · мягкое восстановление растений

Один числовой фильтр для восьми прежних размещений, без новых спрайтов, игровых механик, узлов на пучок и изменений сохранений. Цель — короткое плавное возвращение после выхода героя из радиуса контакта. Конечная приёмка всей первой локации остаётся VMAP-003.

## Поведение и пределы

`FoliageWind` сохраняет исходное поле в `last_contacts`, а в шейдер отправляет `render_contacts` из `FoliageRecovery`. Слой фильтра не меняет геометрию, shader или фазу сортировки. Модуль `RefCounted` хранит только числовые значения, последнее время, мир и физическую позицию. Ссылок на игровые объекты и истории кадров нет.

При положительном шаге часов симуляции применяется `target + (previous − target) × exp(−dt / tau)`: tau=0,08 с при нарастании и 0,18 с при уменьшении длины. Выпуклая комбинация не превышает предел исходного поля 4,36. Совместно с ветром смещение меньше 5,71 и остаётся в прежних PAD12/AABB9. Повторные draw одного такта не интегрируют второй раз; цель берётся от отображаемой стопы, инерционное состояние продвигается только симуляцией.

При нулевой цели и длине ≤0,005 запись удаляется, буфер получает точный ноль. Максимальный последний шаг очистки меньше 0,006 логического пикселя при zoom1,2. Фиксированный буфер64 и максимум64 активных записей; в этой сцене только8 кандидатов. Невидимые индексы удаляются сразу. Один target и две существующие группы переиспользуются.

Пауза останавливает физические часы без накопления долга. Невалидный кадр, перенос, откат часов, большой разрыв физической позиции, low, reduced motion, reference, другая карта и уход за экран очищают след. Остановка героя сохраняет слабый контакт тела; упор не создаёт импульса от нажатой кнопки. `foliage_recovery_enabled=false` или неверный тип дают технический возврат к мгновенному полю VFOLIAGE-005 и очищают фильтр. Это отдельный флаг без нового меню.

## Проверка

Профиль `tools/foliage_recovery_review.gd`: 2553 условия, включая 994 новых и прежние контракты скорости/контакта. Новая suite входит в общий игровой набор. Проверяются 30/60/120 Гц, четыре направления, отсутствие перелёта, полный предел64, повторные чтения одного такта, удаление хвостов, реальные коллизии/пауза/переход и сохранность полного save.

Нативный сбор: `python3 tools/foliage_recovery_collect.py --output <новый-каталог>`; два видимых окна1152×648 и1280×720, логическая сцена1152×648, zoom1,2, target768×384. Только новый профиль `Codex-VFOLIAGE-006-*`. Сцена, фон, герой и растения используют одну фиксированную камеру; background position/scale проверяются отдельно.

59 случаев каждого окна: четыре настоящих прохода с десятью контрольными кадрами, stop/repeat, три паузы, resume, настоящая стена, offscreen/return, low/reduced/reference, интерьер, скачок, невалидный кадр, технические откаты и штатные QA-переносы. Промежуточные физические отсчёты также записаны; Python независимо пересчитывает пространственное поле, скорость по разрешённому смещению и всю экспоненту. Проход обязан пересечь опору и выйти за радиус с противоположной стороны; дальнейшее движение ограничивают настоящие препятствия карты.

Сравнение on/off происходит при одинаковых save, камере и часах. Перед возвратом из QA-отката восстанавливается точное числовое состояние фильтра; тестовая копия не меняет игровой контракт. Каждый вариант содержит два настоящих production callback и четыре draw-сигнала групп с actual uniform/slots/shader/material RID. Отдельная CPU-сетка сверяет шейдерный изгиб и неподвижные нижние полосы.

Четыре lossless APNG содержат нативные кадры; промежутки соответствуют времени симуляции, последний кадр удерживается350 мс перед повтором. Они не являются записью физической клавиатуры или измерением FPS. Все PNG/JSON/логи имеют SHA256; `native/source.json` фиксирует полный production closure на базе Git и отдельный overlay изменённых исходников. Сбор не перезаписывает прошлые принятые данные.

`tools/foliage_recovery_verify.py` и `tools/test_foliage_recovery.py` входят в architecture gate. Отрицательные сценарии портят только копии настоящего evidence: часы, target, затухание, счётчики, callback, GPU-буфер, пиксель и сохранение. Итоговые количества и результаты находятся в `summary.json` и `completion.json`, полные логи — рядом. Wiki проходит сборку, тесты, поиск, изображения/анимации и узкую ширину.

## Ограничения

Это локальное поведение уже подключённых пучков. Не принимаются FPS, стоимость всей карты, физическая клавиатура, другие устройства или вся первая локация. Общая очистка переходного состояния при любых загрузках остаётся VCOMPAT-010. Новые виды, массовая растительность и следующие карточки не реализуются в этой задаче.
