# VFOLIAGE-006: одинаковый стенд Linux/macOS и реальные подсказки HUD

Адресная очередь тимлида относится к текущему PR №1, а не к новой игровой карточке. Обязательные замечания: [P1 экспорт](https://github.com/sergey-leonidovich-shevchenko/babushkina-ferma/pull/1#discussion_r4356305843) и [P2 текст](https://github.com/sergey-leonidovich-shevchenko/babushkina-ferma/pull/1#discussion_r4356305851). Предыдущий общий путь Godot принят ревьюером; run 39902663777 прошёл import/architecture/Wiki, но игра дала 50383/5, поэтому smoke/performance были пропущены.

## Фиксированный вход

`tests/fixtures/preview_portability/` сохраняет четыре источника в PNG **и как сырой RGBA до сериализации**, их размеры, alpha bounds и точные копии четырёх готовых превью из head `dd683fc84e4ad58f246860c8d523a2abaaf83ccd`. Входы проверяются по отдельным SHA файла и RGBA; PNG-декодирование совпадает с оригинальным сырым буфером. Fitter пока прежний, его исходный SHA закреплён. Игровые PNG не менялись.

`tools/preview_portability_capture.gd` не создаёт мир и не импортирует текстуры. Он загружает фиксированный RGBA, вызывает тот же fitter на тех же bounds/160px/8px padding и сохраняет результат с точным offset, координатой, каналом, обоими значениями каждого отличия. Отдельно записаны SHA файла, RGBA и **новой PNG-сериализации**. Последний не называется хешем исходного файла.

`tools/preview_portability.py` пересчитывает отчёт по настоящим PNG; 11 отрицательных/положительных сценариев используют настоящий Godot в маленьком изолированном проекте и портят только временные копии. Изменённый на 1/255 RGB реального reference получает точный отказ даже при нулевой alpha. Диагностический отчёт не может назвать себя игровой приёмкой.

Десять дополнительных сценариев портят копии настоящего HUD: пиксель при обновлённом файловом SHA, локаль, кегль, четвёртую строку, повторённый callback, шрифт/геометрию, save и ложное заявление hardware-приёмки. Отдельно проверяется, что список fallback не заменяет выбор гарнитуры конкретных сформированных глифов. Всего профиль содержит 21 тест.

Отдельный процесс `tools/item_fingerprint_capture.gd` собирает точные файловые/RGBA-отпечатки всех 386 предметов и 275 физических источников, provider/tint и вычисленные результаты прежнего fitter. Он не входит в минимальный процесс и не меняет ресурсы. Данные предназначены для возможного отдельного предметного diff контракта; никакого нового допуска они пока не вводят.

## Матрица и границы

Дополнительный job `Fixed-input reproduction` использует Ubuntu 24.04 x64 и macOS 15 Intel x64. На обеих ОС — официальный Godot 4.7.1, один полный Git hash движка и отдельные проверяемые SHA ZIP. [Официальные релизные файлы](https://github.com/godotengine/godot/releases/expanded_assets/4.7.1-stable), [поддерживаемые GitHub runner](https://docs.github.com/en/actions/reference/runners/github-hosted-runners).

Сбор воспроизводимости — **диагностика**, не замена старому byte-exact тесту. Основной architecture, полный игровой suite, smoke, performance и Wiki сохранены. Допуск 1/255, карантин, allow-failure, перезапись старых архивов или перегенерация игровых ресурсов перед тестом не введены. Причина расхождения libm/float ещё должна быть доказана; новое округление требует отдельного предметного diff и ревью.

## Реальный HUD

Исправлены только три длинные строки: ru/de `player_contact` и ru `fertilizer`. Сохранены попадание после замаха, линия прицела, промах/преграда, отмена невыпущенного удара; удобрения применяются к пустой вспаханной грядке из рюкзака на один сбор, проценты/бонус не изменены. Другие переводы, размер карточки, кегль и правила fitting не менялись.

`tools/ui_portability_capture.gd` снимает настоящий игровой HUD. Для трёх исходных случаев используется явно помеченный старый **текстовый payload** из `tests/fixtures/ui_portability/baseline.json` на текущем коде, а не выдаётся старый бинарник. Затем снимаются обе подсказки на всех шести локалях при 120%. Наблюдатель передаёт каждый вызов прежней отрисовке и записывает фактические семейства/начертания/вес шрифтов, кегль, число строк, width/height/max_lines и process-frame. Полный UI-аудит после исправления должен иметь ноль нарушений; реальная подсказка — не ниже 8 px и не больше трёх строк внутри прежних 268×38 px. Полные save snapshots между четырьмя draw не меняются.

macOS снимается в обычном QA-окне локально. Linux использует настоящий графический путь Godot в Xvfb/Mesa; это виртуальный экран и программный GPU, **не** физическое устройство/FPS/VMAP-003. CI сохраняет PNG/JSON/логи как отдельные artifacts. Сбор в `mac/` содержит фактические локальные данные; результат Linux записывается только после реального CI. `sources.json` связывает сбор с исходниками.

## Воспроизведение

```sh
python3 tools/preview_portability.py
python3 tools/test_preview_portability.py
python3 tools/preview_portability.py --godot /absolute/path/to/Godot --capture /tmp/new-preview-probe --ui
```

Нужен новый output. На Linux графический вызов запускается через `LIBGL_ALWAYS_SOFTWARE=1 xvfb-run -a -s '-screen 0 1152x648x24' ...`; первоначальный editor import нужен только игровому HUD. Исторические материалы VFOLIAGE-006 и VPIPELINE-009 сохранены; задача остаётся `in_progress` и PR draft до полного зелёного CI, повторного ревью окончательного SHA и решения Team Lead Agent.


## Полученные CI-данные и отдельное предложение контракта

Сбор с head `65fb6147c7dc7a0388ebf9eacea73e5e65498a4c`, run [39912695233](https://github.com/sergey-leonidovich-shevchenko/babushkina-ferma/actions/runs/39912695233), сохранён без изменения в `linux-x64/` и `macos-x64/`; IDs artifacts и исходные ZIP SHA — `ci-artifacts.json`. Обе капсулы независимо проверены по файлам/декодированным RGBA. Оба каталога содержат 386 предметов, 275 физических файлов; все source RGBA, формат, размер, bounds, provider/tint и фактические preview PNG/пиксели между ОС совпадают. Отличаются только четыре прямых повторных resize. Минимальный процесс на исходных raw RGBA без игрового мира воспроизводит те же отличия:

| Предмет | x, y, канал | Linux → сохранённый эталон |
| --- | --- | --- |
| wood_dowel | 97, 103, A | 254 → 255 |
| wax_candle | 99, 35, B | 38 → 39 |
| compost | 59, 23, R | 76 → 75 |
| fishing_bait | 111, 54, B | 34 → 33 |

Это локализует различие внутри старого `Image.resize(...LANCZOS)` на одинаковых данных. Точная причина в libm/компиляторе **не доказана**. Исходники [RGBA8 ветки и двух проходов Lanczos Godot](https://github.com/godotengine/godot/blob/a13da4feb8d8aefc283c3763d33a2f170a18d541/core/io/image.cpp#L1045) используют float и преобразование результата в байт; это объясняет место проверки, но не доказывает конкретный источник расхождения сборок.

`tests/fixtures/item_export_contract/manifest.json`, `tools/item_export_contract.*` и `tools/test_item_export_contract.py` — **отдельное предложение, ожидающее ревью**. Оно не подключено к старому `item_sizes_suite`. Конкретный предполагаемый diff включения — `proposed-game-gate.patch`. Предлагаемая семантика: реальные игровые PNG сохраняют точный файловый и RGBA-хеш; каждый источник сохраняет точный физический файл, RGBA, геометрию и идентичность. Повторный экспорт обязан равняться одному из конечного набора полных SHA256, подтверждённых обеими капсулами: один для 382 предметов и два для четырёх. Неизвестный вывод, даже отличающийся на 1/255, получает отказ. Перезаписать игровой preview известным Linux-derived тоже нельзя. Иной движок/fitter/новый предмет требуют явного пересмотра данных; автоматического обновления manifest нет. Это изменение контракта повторного экспорта, не утверждение о прежнем byte-exact успехе; численного допуска нет.

Python проверяет связь всех записей с двумя неизменными капсулами и текущими ресурсами. Отдельный Godot review-процесс выполняет 386 проверок предметов и по шесть отрицательных/контрольных сценариев на каждом спорном предмете; порча происходит только в памяти. Архитектурный и игровой старые gates не удалены, не ослаблены, архивные источники не перегенерированы.

В Linux реальный UI-аудит имеет ноль нарушений; 15 кадров и 60 вызовов подтверждают те же 268×38, не более трёх строк, минимум 8px (RU/DE исправленные строки — 9px). Фактический выбранный Latin/Cyrillic font — DejaVu Sans Book 400; CJK — Noto Sans CJK JP Regular 400. Старые три строки на том же коде воспроизводят кегль 7px и три audit issues. Сбор job завершился **ошибкой записи GLES shader cache**, хотя кадры и аудит корректны. Это не зелёный job. Исправление стенда переносит только имена папок shader cache в новый QA-профиль: GLES инициализирует относительный `user://shader_cache` до смены профиля ([код Godot](https://github.com/godotengine/godot/blob/a13da4feb8d8aefc283c3763d33a2f170a18d541/drivers/gles3/rasterizer_gles3.cpp#L311)); байты кеша, сохранения и настройки не копируются. Проверка ошибок движка остаётся строгой.

Исправленный стенд дополнительно выполнен в настоящем macOS OpenGL: `mac-gl-cachefix/`, 15 кадров/60 callbacks, 36400/0, 28 папок свежего кеша и ни одной ERROR в полном `capture.log`. Это отдельный текущий эксперимент, а не подмена прежней Linux-ошибки. Linux-исправление ещё должен подтвердить новый CI.
