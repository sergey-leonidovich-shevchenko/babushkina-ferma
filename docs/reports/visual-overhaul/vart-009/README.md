# VART-009 — что сохранить и что заменить

Аудит выполнен 17 октября 2026 на состоянии `1b1c39af20b48559904b4a775135305690d0bd10`. [Просмотрщик с поиском](index.html), [полная таблица](DECISIONS.md), [решения JSON](decisions.json), [инвентарь файлов](inventory.json), [паспорт нативной съёмки](native/capture.json), [браузерная проверка](browser.json).

Все **29 семейств** `world_sprite_manifest.json` получили решение с причиной, сохраняемыми частями, объёмом работы, владельцами следующих эпиков и приоритетом. **1 reuse / 16 adapt / 12 redraw**. Единственный reuse — архивный мастер первой карты: он остаётся историческим референсом, а не возвращается в игру целой картинкой. Решение adapt не обещает сохранить каждый пиксель смешанного семейства; исключения перечислены в карточках. Ни один ресурс игры не заменён и не удалён.

## На чём основаны решения

Применены уже выбранные пользователем мягкий стиль A, масштаб 120%, палитра A «Тёплая долина», три стороны предметов, естественный край A, ремесленная фактура B, свет сверху-слева и оба фасада VART-008. Это оценка автора аудита в рамках этих решений, а не новый выбор пользователем 29 готовых production-пакетов. Новые рисунки будут показаны отдельно перед переносом.

Проверены **238 деклараций / 236 уникальных PNG**: размеры, режим, байты, SHA256, общая область альфы, семейства и буквальные ссылки в коде. Два файла повторяются между семействами. Все 236 показаны целиком на 12 обзорных листах; большие атласы там уменьшены только для обзора. Отсутствие буквальной ссылки не доказывает, что файл не используется: есть динамические пути, делегирование владельцев, редактор и совместимость.

Для каждого семейства отдельно выбран один представитель через действительный API владельца: источник, область, назначение и опора сохранены в паспорте. Это не проверка всех кадров всех анимаций. Герой и лиса проходят ту же очистку, что и runtime; их sample PNG не объявляется неизменённой прямой вырезкой из сырого мастера. У AtlasTexture записана область действительного большого источника. Дополнительно просмотрены крупные мастера культур, дерева и фермерских животных: разрешение само по себе не доказывает живописный рисунок.

## Что найдено

- Трава, дороги, пещерный пол, старые вода/всплески, культуры, лесные стадии, малые контейнеры и эффекты требуют нового основного рисунка. На больших исходниках культуры и дерева пиксельная фактура уже присутствует; сглаживание не восстановит отсутствующие мягкие формы.
- У станков, кухни, зданий, фермерских животных и части пещерного декора пригодны конструкция и крупные исходники. Нужны локальная перерисовка, нормализация масштаба/цвета, три стороны и отделение внешней тени. Сохраняются существующие ID, рецепты, уровни, физические размеры и сохранения.
- `WS-014`: у скального ориентира видны чужие фрагменты слева даже в нативном размере. Старое техническое «crop-safe» этого не исключает. В `WS-029` у ткацкого станка видна запечённая на полу тень; её нужно отделить при миграции.
- `WS-017`: настоящая свинья берётся из `farmyard/v1/frames/pig-0.png`, а не из перечисленного старого общего атласа. Мастер животных уже мягче экспортированных маленьких кадров.
- `WS-022`: домашний сундук использует `village_interior_atlas_v2.png`. `WS-025`: сервисная лесопилка делегирует рисунок в Basement. Старый список файлов семьи не равен набору реально выбранных изображений.
- Названия/описания `WS-026/027/029` ещё упоминают четыре стороны; действующий выбор предметов уже ограничен `[0,1,3]`, старый up перенаправляется вниз. В аудите сохранено историческое название семьи, оно не отменяет правило трёх сторон.
- Временная цельная поза обычного кристального хранителя не является готовой направленной анимацией и не относится к боссу `deep_guardian`. Его новый пакет остаётся в VACTOR/VANIM.

Старый статус compliant описывал прежнюю техническую приёмку. Он не означает соответствие новому художественному стандарту. Исправление реестра и удаление прежних файлов потребуют проверки всех потребителей в VPIPELINE/VCOMPAT; этот аудит не выполняет очистку по догадке.

## Как устроены сравнения

Нативный Godot 4.7.1, OpenGL, отдельный профиль `Codex-VART-009-20261017-03`, без создания Game и без доступа к игровым слотам. Физический Image — **1152×648**, поле — **960×540**, фактическая проекция — **1.2**. Каждый readback повторён и совпал полностью.

Слева выбранный старый ресурс в настоящем размере владельца, в центре один текущий герой как линейка, справа принятый материал/модуль VART-008 либо этюд героя VART-006. Правый образец показывает язык формы или материала: мостовой дуб не является готовой новой лесопилкой, фасад не является новым колодцем, а этюд героя не заменяет животное. Фильтрация старого ресурса nearest отражает прежний runtime; новый мастер использует linear с mipmaps. Поведение текстуры, а не только количество пикселей исходника, видно при общей камере.

**58 кадров** — 29 представителей на светлом и тёмном фоне. Из них 56 классифицированы как `world-comparison`, а два кадра `WS-001` — как уменьшенный `archive-overview`. Ещё 12 кадров — `source-overview` всех уникальных файлов, также не мировой масштаб. Всего **70 PNG** плюс 29 отдельных sample PNG. Обзорные листы просмотрены вручную; дополнительно подробно проверены дерево, руда, сезонное дерево, скальный ориентир, свинья, герой, слизень, колодец, лесопилка, кухня, улей и ткацкий станок. Автоматическая браузерная проверка загрузки всех 58 кадров не подменяет просмотр каждой фазы каждой анимации.

Это изолированная витрина, не живое прохождение, не новая сцена игры и не измерение FPS/памяти. Освещение мира, стоимость шейдеров, погода, все ракурсы и последовательности движения здесь не приняты.

## Проверка и воспроизведение

```sh
python3 tools/visual_reuse.py
python3 tools/test_visual_reuse.py
```

Восемь сценариев проверяют покрытие, обоснование и владельцев, потерю файла, неразрешённое удаление/приёмку рисунка, headless/неполный readback, подмену архивного масштаба и последующую независимую замену ассета. `--write` обновляет только производные DECISIONS.md и встроенные данные HTML. Новые игровые ассеты не должны переписывать старый аудит: при изменении текущего файла валидатор сверяет его исторические байты через read-only `git show` из указанного базового commit и SHA256. Для этого в checkout должен быть доступен базовый commit. CI загружает только этот снимок отдельным shallow fetch, без скачивания всей истории. Для локального shallow checkout: `git fetch --no-tags --depth=1 origin 1b1c39af20b48559904b4a775135305690d0bd10`.

Новая съёмка требует нового выходного каталога и уникального профиля; заменять сохранённое доказательство автоматически нельзя:

```sh
tools/Godot.app/Contents/MacOS/Godot --path . \
  --script res://tools/visual_reuse_capture.gd -- \
  --output=/private/tmp/vart009-new-capture \
  --profile=Codex-VART-009-new-capture
```

Это повтор на текущих ресурсах. Для точного исторического воспроизведения нужны базовые ресурсы и владельцы, а также сохранённые инструменты/конфигурация аудита. Имена/даты новой съёмки нельзя выдавать за исходную приёмку.

В браузере проверены 29 выборов × 2 фона, фильтры 1/16/12, поиск «свинья», пустой результат, сброс, размер CSS 1152×648 и 12 ссылок обзора. Откройте `index.html` напрямую либо через локальный сервер, выберите семейство и фон. Все данные встроены, сетевые библиотеки не нужны.
