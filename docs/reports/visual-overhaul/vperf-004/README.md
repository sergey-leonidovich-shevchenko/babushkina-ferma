# VPERF-004 · прозрачные слои травы и воды

Первая локация продолжает использовать прежние рисунки и материалы. При обычном масштабе 120% меш ветра убирает прозрачные поля слева и справа, а композит рисует компактную область травы и камыша. Граница берётся из импортированной альфы с запасом для деформации и фильтрации. Опора, ряды изгиба, размер ветрового target и размещение слотов сохранились. Компактные границы переиспользуются при смене масштаба, пока атлас тот же. На сетке 1× сохраняются исходный меш ветра и полный композит камыша. В первом нативном сравнении на кромке камыша отличились два пикселя альфы на один уровень. Композит травы остаётся обрезанным и на 1×. [Разбор исходных кадров](https://github.com/sergey-leonidovich-shevchenko/babushkina-ferma/pull/99#discussion_r4707897960).

В двух мостах из движущейся поверхности и рисунка дна вычтена только вода за непрозрачной сердцевиной настила. При подготовке renderer проверяет импортированную альфу настила вместе с запасом по краю. Части поверхности после отсечения хранятся в одном меше на водоём с прежними мировыми UV. Геометрия воды для коллизий, рыбалки, берегов, выреза грунта и fallback берётся из прежнего плана. Прямой режим рисует прежнюю полную геометрию. `overworld_render_probe_full_coverage` возвращает обе исходные геометрии только в контрольном экземпляре игры.

## Что сравнивает стенд

- В фиксированных ракурсах двух мостов и плотной травы камера, время, фаза ветра и профиль воды одинаковы в паре. Дополнительный ракурс проверяет мост при неподвижном режиме и масштабе 100%. Кадры снимаются штатным renderer до включения счётчика. Альфа должна совпасть побайтно. Для переинтерполяции UV допускается разница в один код RGB максимум на 0,25% пикселей. Такие пиксели учитываются в отчёте.
- Для каждого ракурса съёмка ждёт видимое окно X11 в фокусе, совпадение размеров окна и framebuffer, готовый кеш земли и видимый слой воды. Нужны восемь подтверждённых отрисовок подряд и не менее 500 мс после настройки окна. Предел ожидания составляет 8 с. При отказе `views/window-error.json` и журнал показывают фактические значения. [Контроль из ревью](https://github.com/sergey-leonidovich-shevchenko/babushkina-ferma/pull/99#discussion_r4706780644).
- Маркер задания и капли на кроне яблони получают фазу фиксированного ракурса. Это позволяет сравнить весь кадр с обычными эффектами, включая неподвижный ракурс моста в дождь. [Разбор капель на кроне](https://github.com/sergey-leonidovich-shevchenko/babushkina-ferma/pull/99#discussion_r4707916994).
- При масштабе мира 100% и 120% первая трава у неподвижного героя получает одинаковый в паре ненулевой изгиб по обеим осям. На 100% RGBA ветрового target на сетке 1× сверяется побайтно, а альфа всего прозрачного композита должна совпасть. На 120% сокращение покрытия проверяется для всего ветрового target на сетке 2× и для слота согнутой травы. Штатный композитор на том же живом атласе снимает отдельный пучок травы. Его альфа должна совпадать точно, а проекция по камере связывает отдельный пучок с полным прозрачным кадром. Два дополнительных снимка измеряют альфа-дельты отдельно при обрезке меша и при обрезке области композита. [Контроль исходного меша](https://github.com/sergey-leonidovich-shevchenko/babushkina-ferma/pull/99#discussion_r4704845238) · [Контроль обрезанного меша](https://github.com/sergey-leonidovich-shevchenko/babushkina-ferma/pull/99#discussion_r4708859957).
- Во всём прозрачном кадре 120% силуэты должны совпадать побайтно. Допуск для соседних несогнутых растений составляет один код альфы максимум на 0,25% покрытых пикселей. Доля считается по покрытым пикселям, чтобы прозрачный фон не увеличивал допуск. В диагностическом пакете из 6 199 покрытых пикселей два соседних пикселя изменились на один код. Для полного игрового кадра на обоих масштабах требуется точная альфа и прежний допуск RGB. [Диагностические PNG](https://github.com/sergey-leonidovich-shevchenko/babushkina-ferma/actions/runs/45894770018/artifacts/15153282557).
- Аддитивная диагностическая маска фиксирует площадь и число слоёв по отдельным каналам для полупрозрачной поверхности воды, композита живой травы и рисунка дна. На отдельном ветровом target считается площадь сеток при тех же фазах. Калибровка 0/1/2 проверяется по сырым PNG. Счётчик включает прозрачные тексели внутри отправленной геометрии. Это геометрическое покрытие выбранных слоёв.
- Два профиля на маршруте дом → мост → площадь → дом используют один Git head, окно и framebuffer 1152×648, мир 120% и seed 20261015. Три парных повтора по 30 с и один парный цикл по 600 с идут последовательно в GitHub Actions на одном Linux/X11 с Mesa llvmpipe. Профиль и физическая симуляция совпадают между вариантами. Вне таймингов выполняются прогрев, диагностические маски и чтение PNG.
- В архиве сохраняются сырые интервалы `frame_post_draw`, p50/p95/p99/max, CPU/RSS, память движка, draw calls и конфигурация. Траектория, фактическая камера и сериализация слота сверяются по каждой паре. GPU-время и аппаратный FPS требуют отдельного измерения. [Контракт предыдущей серии](../vperf-003/README.md).
