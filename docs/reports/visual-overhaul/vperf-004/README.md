# VPERF-004 · прозрачные слои травы и воды

Первая локация продолжает использовать прежние рисунки и материалы. Для живой травы и камыша меш ветра не рисует прозрачные поля слева и справа. Опора, ряды изгиба и UV сохранились. Команда композита больше не выводит весь квадрат `96×96` на растение. Граница берётся из импортированной альфы с запасом для деформации и фильтрации. Компактные границы переиспользуются при смене масштаба, пока атлас тот же. Полный размер ветрового target и размещение слотов сохранились.

В двух мостах из движущейся поверхности и рисунка дна вычтена только вода за непрозрачной сердцевиной настила. При подготовке renderer проверяет импортированную альфу настила вместе с запасом по краю. Части поверхности после отсечения хранятся в одном меше на водоём с прежними мировыми UV. Геометрия воды для коллизий, рыбалки, берегов, выреза грунта и fallback берётся из прежнего плана. Прямой режим рисует прежнюю полную геометрию. `overworld_render_probe_full_coverage` возвращает обе исходные геометрии только в контрольном экземпляре игры.

## Что сравнивает стенд

- В фиксированных ракурсах двух мостов и плотной травы камера, время, фаза ветра и профиль воды одинаковы в паре. Дополнительный ракурс проверяет мост при неподвижном режиме и масштабе 100%. Кадры снимаются штатным renderer до включения счётчика. Альфа должна совпасть побайтно. Для переинтерполяции UV допускается разница в один код RGB максимум на 0,25% пикселей. Такие пиксели учитываются в отчёте.
- В ракурсе контакта у неподвижного героя первая трава получает проверенный ненулевой изгиб по обеим осям. Ветровой target использует масштаб 1. Отдельный прозрачный кадр проходит через тот же композитор травы и проверяет её мягкую альфу. Штатное поле изгиба записывается после настоящего кадра и совпадает между вариантами. [Контроль из ревью](https://github.com/sergey-leonidovich-shevchenko/babushkina-ferma/pull/99#discussion_r4704845238).
- Аддитивная диагностическая маска фиксирует площадь и число слоёв по отдельным каналам для полупрозрачной поверхности воды, композита живой травы и рисунка дна. На отдельном ветровом target считается площадь сеток при тех же фазах. Калибровка 0/1/2 проверяется по сырым PNG. Счётчик включает прозрачные тексели внутри отправленной геометрии. Это геометрическое покрытие выбранных слоёв.
- Два профиля на маршруте дом → мост → площадь → дом используют один Git head, окно и framebuffer 1152×648, мир 120% и seed 20261015. Три парных повтора по 30 с и один парный цикл по 600 с идут последовательно в GitHub Actions на одном Linux/X11 с Mesa llvmpipe. Профиль и физическая симуляция совпадают между вариантами. Вне таймингов выполняются прогрев, диагностические маски и чтение PNG.
- В архиве сохраняются сырые интервалы `frame_post_draw`, p50/p95/p99/max, CPU/RSS, память движка, draw calls и конфигурация. Траектория, фактическая камера и сериализация слота сверяются по каждой паре. GPU-время и аппаратный FPS требуют отдельного измерения. [Контракт предыдущей серии](../vperf-003/README.md).
