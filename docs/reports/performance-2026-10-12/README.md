# Нативная производительность — 12 октября 2026

Целевой p95 действительно отрисованного кадра ≤20 мс выполнен во всех восьми сценариях на этом компьютере. Итоговые данные находятся в `final4`; `tools/check_native_frame_reports.py` независимо пересчитывает p95 из сырых интервалов. TD-PERF-007 закрыт для этих условий. Другие GPU, активное окно и продолжительные сеансы требуют отдельного контроля.

## Изменения

- Неподвижный грунт деревни собирается существующим модульным renderer в SubViewport 2400×1368 с UPDATE_ONCE. Повторный кадр использует одну текстуру; смена сезона или погоды пересобирает кеш. Коллизии и исходные спрайты остаются общими с прежним чертежом. Кеш принадлежит сцене, не записывается на диск и занимает около 12,5 MiB RGBA дополнительно.
- Невидимые деревья, плодовые растения и фермерский двор отсекаются по камере с запасом для тени и анимации. Их симуляция продолжается.
- F10 получает один пакет до 1 мс за render-кадр. Полное поколение публикуется атомарно; профильный тест проверяет завершение и все настоящие причины клеток.
- Engine.max_fps=0, VSync сохраняет пользовательскую настройку. OS.low_processor_usage_mode с ожиданием 500 мкс не отправляет сотни одинаковых Canvas-кадров между физическими тиками. Игровая физика остаётся 60 Гц.

В оконной деревне F10 среднее число draw calls снизилось примерно с 644 (`town-cpu-v2`) до 225 (`terrain-cache`). Это сравнение диагностических прогонов, а не процент увеличения FPS.

## Итоговый контроль

Godot 4.7.1, Compatibility/OpenGL, AMD Radeon Pro 5300M. 120 проходов прогрева с замороженным миром; затем не менее 25 секунд симуляции и 1400 process-сэмплов. В таблице только события RenderingServer.frame_post_draw: около 1500 реальных кадров в каждом прогоне. Последовательные процессы, без тяжёлых параллельных проверок. Seed 20260908, ru, масштабы 100%, звук включён, screen shake выключен. Физическое управление клавишами, без телепорта.

## Как воспроизвести

```sh
./tools/Godot.app/Contents/MacOS/Godot --path . --script tools/runtime_frame_review.gd -- --profile-town --report-dir=res://docs/reports/performance-2026-10-12/repeat/window
./tools/Godot.app/Contents/MacOS/Godot --path . --script tools/cave_boss_frame_review.gd -- --report-dir=res://docs/reports/performance-2026-10-12/repeat/window
```

Добавить `--benchmark-debug-overlay` для F10 и `--profile-fullscreen` для фактического полного размера; использовать разные папки. Проверка опубликованных восьми файлов: `python3 tools/check_native_frame_reports.py`.

`frame_intervals_ms` и исторический ключ `render_frame` описывают проходы SceneTree._process, включая циклы без нового GPU-кадра. Оценивать производительность по ним при on-demand режиме неправильно. Достоверный интервал отрисовки находится в `draw_intervals_ms` / `draw_frame`. Старые и неудачные диагностики (`vsync`, `timer`, `demand*`, `final*`, CPU-профили) сохранены; они не подменяют итоговый контроль. До исправления реального полноэкранного размера некоторые файлы с mode=3 всё ещё имели 1152×648.

## Проверка рисунка

`tools/terrain_cache_review.gd` сравнивает непосредственный рисунок и кеш в окне 1:1 для spring/clear, summer/rain, winter/snow. [Сырые пиксельные метрики](terrain-cache-pixels.json) и шесть native PNG сохранены рядом. Визуально рисунок проверен. Отдельный framebuffer меняет субпиксельную растеризацию некоторых краёв: примерно 0,13% пикселей различаются; это не побитовое совпадение. Допуск стенда: не более 0,15% каналов с отличием >1 и средняя ошибка <1 из 255. Смена сезона/погоды действительно обновляет текстуру.
