## Объём и границы

[Принятая исходная группа](baseline/inventory.json) содержит71 назначение:61 исходник (35 Python/26 GD),8 tracked UID и2 JSON. Они перемещены в `tools/assets/contracts`, `tools/assets/migration`, `tools/build`;18 ignored UID сохраняют байты/mode/ignored-состояние. Корень481→420. [Первичная карта](migration-initial.json) относится к механическому шагу до адресных доработок; окончательные SHA находятся в [повторном профиле](profile-02.json). Установленный движок, runtime/assets/сохранения и старые доказательства не перемещаются.

`source_paths` — фиксированная таблица71, не загружаемая из metadata. `current_source` выбирает canonical файл и отказывает на symlink/traversal; отсутствующий новый адрес не скрывается старой копией. `historical_source` выбирает единственный old/new alias только из дерева того Git commit, который уже читает caller. Старые `POLICY`/SOURCES/ключи документов остаются логическими. Два JSON побайтно прежние, включая пять provenance source pins. Неполная/неизвестная metadata-карта не выбирает иной файл.

Связанные Python imports и GD preload/self-SHA обновлены;11 живых code consumers включают CI, architecture, root CLI других семейств, exporter и игровой suite. Migration fixture по-прежнему копирует соседний capture в собственный старый namespace `fixture/tools/migration_capture.gd`; это действительный внешний протокол. Его тело, Fitter и оба asset-probe сохраняют прежние байты. Текущие тестовые проекты получают canonical ресурсы без дублирующих legacy-копий.

Два исторических reader закрепляют прежние collector blobs полного main/D609: VART010 icons и legacy preview. Свежий preview пишет точный `source_paths` и SHA текущего файла; новая карта требует новые фактические байты. Удаление карты, подмена на старый SHA или неизвестный путь отклоняются. Fitter сохраняет прежний FITTER_HASH, а PNG/RGBA/численные сравнения не меняются. Генераторы изображений и старые captures не запускаются с записью в прежние отчёты.
