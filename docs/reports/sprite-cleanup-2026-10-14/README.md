# Очистка неиспользуемых спрайтов · 14 октября 2026

Удалено **90 неиспользуемых графических ресурсов**: 8 PNG и 82 описания AtlasTexture `.tres`. Освобождено **6 356 484 байта ≈6,06 МиБ** исходных файлов рабочей копии. Дополнительно убраны 8 производных `.import`, из них 4 отслеживались Git, 4 были локальными результатами импорта. Это очистка файлов, уже не участвовавших в игровой загрузке; новый FPS или уменьшение VRAM этим изменением не заявляются.

Исходная версия:0.0.168, коммит `dd01a10cf4337606286a3d9cb5e414c0b108bbe4`. Пиксели оставшихся изображений, игровые правила, тексты, атласы используемых предметов и внешний вид не изменялись.

## Что сохранено

- Все385 крупных превью и общий миниатюрный атлас.162 из этих превью попали в первоначальную текстовую выборку, поскольку пути собираются из ID. Реальное обращение к двум размерам каждого предмета подтвердило их использование.
- Исходники/мастера растений, персонажей, станков, выбранных и ещё не выбранных макетов. Эталонные изображения UI остаются нужны визуальным тестам; актуальные контрольные кадры имеют живые ссылки.
- Девять старых задних PNG мебели: записанные пользователем уровни хранят буквальный `asset_path`. До отдельной миграции этих путей удаление файла могло бы сделать такой уровень невалидным. Они скрыты из текущего каталога и не загружаются обычной мебелью; резерв перечислен в `reserved_legacy_png` манифеста. Новая мебель и старое направление2 по-прежнему показывают разрешённый передний ракурс.
- Одиннадцать контрольных кадров зданий, интерьеров и окружения: тесты загружают их по форматным путям `building_%s_ingame_preview.png`, `interior_%s_ingame_preview.png` и `environment_%s_ingame_preview.png`. Первый полный прогон выявил этот пробел статической выборки:28 718 успешных проверок и11 ошибок. До публикации все11 эталонов возвращены, форматные пути добавлены в защиту и регрессионные тесты. Список сохранён в `reserved_test_previews`; игровые проверки не ослаблялись.
- Лицензии и сведения о происхождении. История Git остаётся доступна; концепты не переносятся в игровые ресурсы и не дублируются ради архива удалённой партии.

`sprite_usage_review.gd` создаёт отдельный профиль `Codex-Sprite-Usage-20261014`, не читает слоты игрока. Проверяются оба размера иконок, все уровни/кучи, все четыре старых индекса направления, включая совместимость2→передний вид. Списки ресурсов записаны без нестабильных instance ID. Это контроль источников и геометрии, а не новое измерение GPU/FPS.

`check_sprite_cleanup.py` блокирует возвращение удалённых файлов/sidecar, прямую или относительную ссылку на них, форматные пути потребителей игры/тестов/Wiki (`%s`, `%02d`, `{id}`, `${id}`), удаление динамически используемого ресурса, исчезновение зарезервированного эталона/старого PNG, повтор ID, подмену хеша и выход за `assets`. Одиннадцать fixture-тестов проверяют эти отказы. Форматные пути сборщиков в `tools/` разбираются вручную: одни читают исходники, другие создают выходные файлы; шаблон записи сам по себе не доказывает использование результата. Обе команды подключены к архитектурному gate. Такой guard защищает конкретную проверенную партию; он не объявляет все остальные ресурсы автоматически безопасными для удаления.

Сборщики ремёсел, кухни и подвала больше не создают задние `.tres`. В таблице ремёсел прежний индекс2 остаётся псевдонимом переднего. Подвальный сборщик выгружает ресурсы и метаданные, сохраняя актуальный прикладной renderer: его особые передние виды и миграция направлений не перезаписываются старым шаблоном. Нарезчики проверены компиляцией Python; графика заново не нарезалась.

## Воспроизведение и восстановление

```sh
python3 tools/test_sprite_cleanup.py
python3 tools/check_sprite_cleanup.py
tools/check_architecture.sh
./run_tests.sh
```

Для повторной фактической инвентаризации сначала записать JSON-массив путей PNG/TRES в `/private/tmp/moon-valley-sprite-files.json` из `git ls-files`, затем выполнить:

```sh
./tools/Godot.app/Contents/MacOS/Godot --headless --path . --script res://tools/sprite_usage_review.gd
```

Результат — `/private/tmp/moon-valley-sprite-usage.json`; сырые снимки этой партии сохранены рядом с отчётом. Перед очередной партией нужен новый актуальный снимок, проверка форматных/динамических загрузчиков и разбор оставшихся кандидатов. Для удалённого файла можно использовать `git restore --source=dd01a10 -- <путь из removed.json>`; это восстановит рабочую копию без переписывания истории. Guard затем потребует осознанно пересмотреть партию.
