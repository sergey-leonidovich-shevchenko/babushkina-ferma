# Читаемость контактных теней

Сценарий VSHADOW-010 использует настоящую игру, четыре существующие точки: ферма, улица, роща и дом. День и сумерки снимаются без bloom при 1152×648 и 1280×720. Восемь отдельных процессов дают production, прозрачный прибор, выключенные контакты и кадр без трёх тестовых предметов. Новые карты и игровые механики не добавляются.

```sh
python3 tools/run.py qa.world.shadows.collect --output /private/tmp/новая-папка
python3 tools/run.py qa.world.shadows.verify --input /private/tmp/новая-папка
python3 tools/run.py qa.world.shadows.test_contract
python3 tools/run.py qa.world.shadows.test_hook_context
python3 tools/run.py qa.world.shadows.test_readability
```

`test_hook_context` запускает настоящий `git commit`/pre-commit в собственной временной linked worktree с `extensions.worktreeConfig=true`. Один и тот же test case исполняется из принятого старого commit и текущего файла. Старый вариант воспроизводит переключение `core.bare` только у временного родителя; исправленный сохраняет его config, оба index, HEAD/refs и окружение. Setup Git-команды всегда очищают `GIT_*`; отрицательный внутренний запуск допускается только внутри помеченной временной папки, с Git-pointer в её собственный common directory. В рабочем проекте отрицательный опыт не выполняется.

Нативный сборщик требует macOS, установленный официальный Godot4.7.1 и свободный QA-дисплей. Перед каждым запуском он проверяет занятость, использует собственный профиль с UUID и новый внешний каталог. Рабочий проект и сохранения игрока не используются. Выполняются Git-export и свежий импорт ресурсов. Единственная инструментация в контрольной копии касается семи владельцев контактов; свечение фонаря, тела предметов и порядок игровых проходов сохраняются. Логи, точные команды, скрипты, UID и хеши сохраняются. При таймауте закрывается только собственный процесс с совпавшими движком и UUID-профилем. Прерванная серия не принимается.

Статичный QA отключает `OS.low_processor_usage_mode` только в своём процессе: иначе неподвижный кадр может не породить ожидаемый `frame_post_draw`. Обычная игра сохраняет экономию ресурсов. Чтение framebuffer идёт после очереди redraw, `process_frame` и завершения рендера; принудительный draw до отложенных команд не используется.

Reader работает без дисплея и движка. Он сверяет закреплённые Git trees, точные QA-входы, ограниченные overlays, полный набор артефактов, фактические argv, состояния до/после и пары камер. Все RGBA production и варианта с включённым прибором должны совпасть. Изменения при отключении теней разрешены только внутри зарегистрированных bounds с запасом2px. Каждый предмет должен иметь видимую непрозрачную сердцевину; тень поверх неё вызывает отказ. Исходные alpha берутся из реальных маленьких текстур, сохранённых движком.

`--width 1152` либо `--width 1280` у сборщика создаёт диагностическую серию. Для её чтения требуется `verify --diagnostic`; результат получает `acceptance_eligible=false`. Остановленная симуляция, наличие PNG и зелёный reader не являются замером FPS, приёмкой солнечной проекции или всей первой локации. Художественные кромки дополнительно проверяются по самим кадрам.

Из другой рабочей папки передайте абсолютный путь к `tools/run.py`. Для запуска с враждебными Git/Python переменными штатный launcher изолирует импорты, а сборщик читает собственный Git без унаследованных directory/config overrides.

При проверке ещё не закоммиченного исправления добавьте сборщику `--working-candidate`. Это явно сохраняет ровно два игровых файла в `candidate/`, их исходные и новые SHA, а также `source_state=working-tree`. Остальное берётся из закреплённого Git-export. Такой пакет не обозначается кадрами неизменённого base commit. Перед публикацией выполните `verify --check-current-candidate`: текущие runtime и QA-входы должны побайтно совпасть с замороженными. Обычный reader позже проверяет исторический пакет, не требуя прежнего содержимого будущей рабочей ветки. Номер версии и выпуск FPS этим не принимаются.
