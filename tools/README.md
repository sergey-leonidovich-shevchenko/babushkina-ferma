# Инструменты проекта

REFACTOR-02 сначала готовит общие границы запуска и Git, затем переносит только 14 файлов quality/planning по принятой ведомости. QA/asset/build-переносы остаются REFACTOR-03. Движок `tools/Godot.app` и игровые ресурсы не перемещаются.

Общие функции лежат в `common`: корень определяется по исходнику и маркерам `project.godot`, `VERSION`, `tools`, без зависимости от cwd, глубины или Git-окружения. `run.py` запускает собственный Python-модуль и сохраняет аргументы, вывод и exit. Например, на подготовительном этапе: `python3 /полный/путь/tools/run.py project_backlog`; после переноса — `python3 /полный/путь/tools/run.py planning.project_backlog`. Текущий каталог не меняется. Внутри процесса временно доступны выбранный проект и legacy-корень tools для ещё не перенесённых импортов; глобальный PYTHONPATH не устанавливается.

`__init__.py` в корне tools закрепляет собственный пакет, чтобы внешний пакет с тем же именем не подменил команду. Это один дополнительный package marker к прогнозу девяти корневых исходников аудита: итоговый бюджет остаётся не более 30. Принятая историческая ведомость не переписывается.

Git-команды, адресованные отдельному репозиторию, получают копию окружения без `GIT_*`. Это предотвращает повреждение родительских config/index внутри hooks и disposable проверок. Законный alternate index текущего commit hook для `bump_version --stage` сохраняется; очистка не выполняется глобально в родительском процессе.

Публичные совместимые входы после пилота: `check_architecture.sh`, `bump_version.py`, `task_batch.py`; они будут делегировать единственной реализации. Остальные принятые корневые входы `smoke_test.sh`, `performance_gate.sh`, `performance_gate.py` и защищённые `performance_sampler.gd`/`water_audit.gd` пока не меняются. Причины полного публичного списка и будущие пути сохранены в `docs/reports/refactor-01/integration-1/snapshot/migration-plan-copy.json`. Дополнительные wrappers для каждого старого имени не создаются.

Проверка инфраструктуры: `python3 tools/run.py common.test_infrastructure`. Она использует настоящие disposable Git/worktree, проверяет argv/exit, подмену пакета, ссылки вне tools, нулевой unittest, чужое Git-окружение, alternate index и вложенный архитектурный лимит. Установленный движок, кеши и чужие репозитории остаются за пределами этих fixtures.
